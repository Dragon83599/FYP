# 把演示页变成真正的 PWA（手机不依赖电脑）

> **已完成（2026-11-04）**：部署在 **https://dragon83599.github.io/FYP/**，
> 走的是下面 §3 的 **路线 C（GitHub Pages）**，分支 `pwa-export`。
> 手机已安装，关掉电脑 + 飞行模式下自检仍通过。下文保留三条路线，作为换托管时的参考。

> 结论先说：**算力已经在手机上了，缺的只是"文件交付"这一步**。
> 要做到关掉电脑也能用，必须把 `pwa/` 放上一次 **HTTPS** 静态托管，装到桌面一次，之后完全离线。

## 1. 为什么现在还不算 PWA

| | 现在（`http://192.168.43.172:8080`）| 目标（`https://…`）|
| --- | --- | --- |
| 推理在哪跑 | **手机**（WebGL） | 手机 |
| 文件从哪来 | **每次都要电脑上的服务** | 首次访问后**缓存在手机里** |
| 电脑关机 | ❌ 打不开 | ✅ 照样打开 |
| 能否安装到桌面 | ❌ | ✅ |
| 断网 | ❌ | ✅ |

硬约束：**Service Worker 只在安全上下文（`https:` 或 `localhost`）注册**。
`http://192.168.x.x` 属于不安全上下文，浏览器**直接拒绝**——不是我们没写，是浏览器不让。
所以手机上那块会显示"当前是 http:// 局域网地址…关掉电脑就打不开"，这是**如实告知**，不是坏了。

## 2. 需要部署的文件

整个 `pwa/` 目录，约 **1.8 MB**（含 1.5 MB 的 `tf.min.js`）。关键是这些必须一起上去：

```
index.html  app.js  diag.js  pwa.js  preprocess.js  wav.js
manifest.json  sw.js  filters/  icons/  model/  vendor/
```

`model/` 里有 `model.json` + 权重 + 自检用的 `reference.json` 和 `New_AS_001.wav`。
**不想要那条真实录音公开**的话，删掉 `model/New_AS_001.wav` 与 `reference.json` 也能部署，
代价是页面上的"跑一致性自检"会失效（演示推理仍然可用）。

## 3. 三条托管路线（都能拿到 HTTPS）

### A. Netlify Drop（最快，拖拽上传）

1. 打开 <https://app.netlify.com/drop>，登录；
2. 把 **`pwa` 整个文件夹**拖进去；
3. 拿到 `https://<随机名>.netlify.app`；
4. 手机打开 → 浏览器菜单"安装应用/添加到主屏幕" → 完成。

### B. Cloudflare Pages（Git 或直传）

1. <https://pages.cloudflare.com/> → "Upload assets" 或连 GitHub 仓库；
2. 构建命令留空，输出目录填 `pwa`；
3. 拿到 `https://<项目>.pages.dev`。

### C. GitHub Pages（已经在用 git，最省心）

```bash
# 只把 pwa/ 放到一个独立仓库（不要把整个 FYP 仓库推上去）
cd /home/psr/FYP
git subtree split --prefix=pwa -b pwa-export
git push <你的仓库> pwa-export:main      # 或用 gh repo create
# 仓库 Settings → Pages → Source: main / root
```

得到 `https://<用户名>.github.io/<仓库名>/`。
注意：**GitHub Pages 的免费版要求仓库公开**；`model/New_AS_001.wav` 是 Yaseen 数据集里的一条样本，
公开前请先决定是否保留（见 §2）。

### 不推荐：隧道（cloudflared / ngrok）

能给 HTTPS，但**服务仍跑在电脑上**——电脑一关就没了，所以它解决不了你问的这个问题，只适合临时测试安装流程。

## 4. 部署后怎么确认真的成了 PWA

手机上打开 `https://…` 后：

1. 页面"离线能力"那行应显示 **"离线可用：已缓存全部文件"**（不是红字）；
2. 浏览器菜单出现 **"安装应用 / 添加到主屏幕"**，点了之后桌面多一个图标；
3. **关掉电脑**（或开飞行模式），从桌面图标打开 → 页面照常打开、"跑一致性自检"照常通过。

第 3 步是唯一有说服力的验收：**电脑关机 + 手机飞行模式，仍然得出 1.88e-12**。

## 5. 更新版本时要注意

`sw.js` 里：

```js
const CACHE_VERSION = "pcg-demo-v1";   // 改文件内容就 +1
```

不改版本号，手机会一直用缓存里的旧文件（这正是离线的代价）。改完重新部署，
页面会提示"发现新版本，正在更新缓存…"，再刷新一次即为新版。

`npm test` 里有一条测试会检查：**页面请求的每个文件都必须在 `PRECACHE` 列表里**——
漏一个就会出现"在线能用、离线白屏"，而那种 bug 在演示现场才暴露。

## 6. 与论文口径的关系

- 现在可以写的事实：**推理在本机完成、无任何外部请求**（已核对：页面所有请求都是同源相对路径）。
- 部署到 HTTPS 并安装后，可以再写一条更强的：**首次加载后完全离线可运行**，且这是 PWA 的定义性能力。
- 但**不要**把"端侧"说成"不需要任何服务器"——首次分发总要有个 HTTPS 静态站点；
  这条与"运行时不需要服务器"是两件事，写清楚反而更可信。
