### 2. E4（工程估算）
**不是实测、不是文献原文，是我按原理推的。**

| 等级 | 含义 | 例子 |
| --- | --- | --- |
| 一手 | 标准、datasheet、官方实测 | 芯片手册写 SRAM 512 KB |
| 独立实测 | 论文里真跑过 | Ma 报 20,193 参数 |
| 厂商宣称 | 厂家说好，没人复现 | "NPU 600 GOPS" |
| **E4** | **我算的/我估的** | **改进点"预期 +1~2 点"** |

> 论文里凡 E4 的，写"本文采用"，**不能写"文献表明"**。

### 3. ADR（架构决策记录）
一个决策一张卡：问题、候选、数据、结论、验证方法、回退方案。编号 ADR-020 至 ADR-048。

> **比方**：像病历——不只记"吃了什么药"，还记"为什么开这个药、什么情况换药"。

### 4. 置信区间（CI）
**一个范围，真值有 95% 可能落在里面。** 不是"他 180"，而是"他 176–184"。

**为什么必须有**：两个模型 98.6 与 98.9，若区间 ±0.5，这 0.3 就是噪声。

### 5. 泄漏（leakage）
**训练时不小心看到了测试信息**，指标虚高，上线就崩。如同**考前偷看答案**。

**我们的例子**：19 先把 1,000 条增强成 15,000 条**再**划分 → 98.48 冲到 **99.87**。

### 6. 消融（ablation）
**把某个部件拿掉，看指标掉多少**——证明"这个部件有用"的唯一办法。

**我们的情况**：文献里有人用 HSMM 分割，但**没人做"拿掉分割"的对照**，所以我不能说"分割有用"（第 10 页）。

## 二、三条路线（第 3–5 页）

| 词 | 是什么 | 比方 |
| --- | --- | --- |
| **PWA** | 渐进式网页应用，能"装"到手机桌面，本质是网页 | 网页版 App |
| **SBC** | 单板计算机（树莓派那一类）| 小电脑 |
| **MCU** | 单片机（STM32、ESP32、nRF52）| 小计算器 |
| **TF.js / WebGL** | 在浏览器里跑模型的库 / 调用 GPU 的接口 | 借用手机显卡 |
| **PC 端精度** | 在电脑上用浮点数跑出来的精度 | 训练时的成绩 |
| **端侧精度** | 部署到设备后（可能量化/裁剪）的精度 | 上场比赛的成绩 |
| **端上时延** | 设备上跑一次推理要多久 | 出餐时间 |
| **RTF（实时因子）** | 处理耗时 ÷ 音频时长；**≤1 才算实时** | 1 秒的活要在 1 秒内干完 |

## 三、复现基线（第 9 页）

| 词 | 是什么 | 说明 |
| --- | --- | --- |
| **17 号文献** | 我们要 1:1 复现的那篇（Ma 2023）| 全篇统一用编号，不用 L 前缀 |
| **1 kHz / 2 s / 2,000 点** | 采样率 / 窗长 / 输入长度 | 1,000×2 = 2,000 |
| **16-8-4** | 三层卷积的通道数 | 每层用几个"印章" |
| **池化 4** | 每 4 个点压成 1 个 | 长度 ÷4 |
| **FC128** | 全连接层 128 个神经元 | 参数主要在这 |
| **tanh** | 一种激活函数（平滑的 S 形）| 给网络加"非线性" |
| **20,193 参数** | 模型里要学的数字个数 | 旋钮数量 |
| **98.65%** | 原文报告的精度（**PC 端、随机 10 折**）| 我们的验收门围绕它 |
| **验收门 ±1.5 点** | 复现结果必须落在 97.15–100 之间 | 超出就停 |
| **随机折 / 录音分组折** | 按随机切 / 按"同一条录音不跨折"切 | 后者更严，通常低 1–3 点 |
| **HSMM 分割** | 把心音切成 S1/S2 段的算法 | 27 用它，成本高 |

## 四、五个改进涉及的词（第 10 页）

### I1 采样率（第 10 页）
| 词 | 一句话 |
| --- | --- |
| **采样率** | 每秒采多少个点；2 kHz = 每秒 2,000 点 |
| **Nyquist** | 采样率的一半，是能表示的最高频率；**2 kHz → 上限 1,000 Hz** |
| **500–600 Hz** | 22 指出异常成分能到这么高；1 kHz 采样的上限正好 500 Hz → **砍在带边** |

### I2/I3 窗长与对齐（I3 在第 10 页；I2 已砍）
| 词 | 一句话 |
| --- | --- |
| **窗长** | 每次分析多长的一段音频（我们 2 s）|
| **滑动窗** | 每次往前挪一点（我们挪 1 s）|
| **S1 对齐** | 把窗平移，让第一心音落在固定位置（**只平移不重切**）|
| **F1（此处指分割）** | 33 报告 S1 分割 F1 **98.5%**、S2 **97.2%** |

### I4/I5 表示（I4 在第 10 页；I5 已砍）
| 词 | 一句话 |
| --- | --- |
| **原始波形** | 直接喂 2,000 个采样点 |
| **MFCC** | 把频谱压成十几个倒谱系数（有损压缩）|
| **log-mel** | 取对数后的 mel 谱（64 个频带能量）|
| **CWT / CQT / STFT** | 另外几种时频变换（得到二维图）|
| **网格搜索峰值** | 在一堆配置里挑最高分——**很可能是噪声里的最高点** |

### I6 结构（**已砍**，仅备查）
| 词 | 一句话 |
| --- | --- |
| **分组卷积** | 把通道分组做卷积，省参数（27 省到 **38.1%** 参数、**11.7%** FLOPs）|
| **早期池化** | 尽早缩短序列长度，压小后面的全连接层 |
| **GAP** | 整张特征图取平均，替代大 FC |
| **KWC** | 26 的通道加权模块（涨点，但 312k 参数）|

### I7/I8 训练（I7 在第 10 页；I8 已砍）
| 词 | 一句话 |
| --- | --- |
| **数据增强** | 造更多训练样本（平移/加噪/变速）|
| **泄漏（增强）** | 先增强再划分 → 同一条录音的副本跨折 → 指标虚高 |
| **SSL（自监督）** | 自己造任务预训练（如判断"有没有被翻转"）|

### I9 损失与 I10 聚合（**均已砍**，仅备查）
| 词 | 一句话 |
| --- | --- |
| **类别加权 / focal loss** | 让模型更关注少的类别 |
| **类不均衡** | 各类样本数差得多（我们窗数最大/最小 **1.31×**）|
| **窗级 / 录音级** | 按每个 2 s 窗算 / 按整条录音算 |
| **soft voting** | 把多个窗的概率平均成录音级结论 |

### I11 量化（**已砍**：17 原文未量化；PWA 轨也不需要）
| 词 | 一句话 |
| --- | --- |
| **int8 / int16** | 用 8 位 / 16 位整数存权重（省内存）|
| **PTQ** | 训练后量化：直接压，不重训；**17 原文没做量化，用的是 float32** |
| **QAT** | 量化感知训练：训练时就模拟压缩 |
| **掉点** | 端侧精度比 PC 低多少 |
| **裁剪 vs 量化** | 27 掉 3.8 点是**裁剪模型**造成，不是量化 |

## 五、评估（第 10 页：判据一句）

| 词 | 一句话 | 比方 |
| --- | --- | --- |
| **单轴改进** | 一次只改一个变量 | 一次只换一个零件 |
| **CI 不含 0** | 差值区间不跨 0 → 差异是真的 | — |
| **≥0.5 点** | 实质差异门槛（太小不值得写）| — |
| **macro F1** | 每类各算 F1 再平均（不看样本多少）| 五个班平均分 |
| **kappa** | 扣掉"瞎猜也能对"之后的一致性 | 去掉运气成分 |
| **混淆矩阵** | 真实类别 × 预测类别的表 | 错题分布表 |
| **cluster bootstrap** | 按录音分组重采样 | 抽样时要整条整条抽 |
| **AUC（我们拒绝报）** | 排序质量指标；文献里多是二分类口径，与我们不可比 | — |

## 六、部署与证据（第 6–7 页）

| 词 | 一句话 |
| --- | --- |

## 七、被问时的八个一句话答案

| 问题 | 一句话 |
| --- | --- |
| 为什么选 PWA？ | 零硬件成本：屏幕与算力都自带（采集用队友设备）|
| 为什么砍树莓派？ | 角色被 PWA（端上证据）与 PC（浮点基线）覆盖 |

| 为什么不堆模型？ | 参数 ×34 只多 0.28 点（23 vs 24）|
| 为什么 SSL 不优先？ | 17 只 +0.78；18 在 100% 标签时无增益 |
| 为什么三个种子？ | 26 单次结果无法区分方差 |
| **你的结果呢？** | **还没有——第 6 页是复现计划，结果在 W3 之后** |

## 九、三个最容易说错的口径

| 别说 | 要说 |
| --- | --- |
| "手机能跑，所以我们也行" | **手机能跑已被 17 与 44 证明；我们的模型在浏览器里多快还没测** |
| "精度 99%" | 必须带位置：`PC · float · 99.4%` 或 `端侧 · int8 · 95.6%` |
| "端到端系统" | **端侧推理**（采集是合作者的工作，不声称端到端）|
