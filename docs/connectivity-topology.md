# 连接拓扑与链路 B 决策

> 状态：已确认主机和手机可以使用 Wi-Fi 连接
>
> 更新日期：2026-10-07

## 1. 更新后的拓扑

```text
无线探头
  -> 链路 A：BLE 5.0 GATT
独立主机
  -> 链路 B：Wi-Fi
手机 / 本地服务器
  -> 可选云端服务器
```

链路 A 仍负责探头到主机的低功耗实时音频传输。链路 B 改为 Wi-Fi 后，主机
只需要作为 BLE central 连接探头，不再需要为了连接手机同时充当 BLE
peripheral。这个变化降低了 BLE 多角色调度风险。

## 2. Wi-Fi 连接模式

| 模式 | 拓扑 | 优点 | 限制 | 建议 |
| --- | --- | --- | --- | --- |
| 主机 SoftAP | 手机连接主机热点 | 无路由器也能使用，现场部署简单 | 手机可能提示热点无互联网；云端上传依赖手机蜂窝网络或后续切换网络 | 便携模式默认方案 |
| 外部 AP | 主机和手机连接同一路由器 | 主机可直接访问本地服务器或互联网，吞吐和路由最自然 | 必须有可用 AP，现场配置增加 | 临床/实验室模式默认方案 |
| 手机热点 | 主机连接手机热点 | 不依赖外部路由器，手机网络可直接供主机使用 | 手机热点功耗高，配置和重连受系统限制 | 备用方案 |
| Wi-Fi Direct/P2P | 主机与手机直接组网 | 不依赖 AP，性能较高 | iOS 对通用 Wi-Fi Direct API 不可靠，跨平台成本高 | 不作为主方案 |

建议同时实现前两种模式：

- 无网络环境：主机开 SoftAP，手机 App 连接主机并控制测量。
- 有网络环境：主机和手机连接外部 AP，主机直接上传本地服务器或云服务器。
- 云端上传不要求实时完成。链路 B 断开时，主机继续采集、显示、回放和边缘 AI，恢复连接后再同步。

## 3. 链路 B 协议建议

- 测量控制和实时状态：WebSocket 或等价长连接。
- 文件、原始音频和报告：HTTPS 上传。
- 云端异步消息：MQTT over TLS，或继续使用 HTTPS，具体由服务端方案决定。
- 本地 Wi-Fi 不能替代应用层安全。涉及患者数据时，即使在同一局域网，也应使用 TLS、设备身份和访问控制。
- iPhone App 首次访问局域网设备时需要处理本地网络权限提示。

## 4. 新验收项

- 主机能同时运行 BLE central 和 Wi-Fi station/SoftAP。
- Wi-Fi 连接建立和断开不影响链路 A 的连续采集。
- 主机 SoftAP 模式可完成手机连接、控制和数据查看。
- 外部 AP 模式可从主机直接访问服务器。
- 手机连接主机 SoftAP 且同时使用蜂窝网络时，明确云端上传是否由手机转发，或改为测量结束后批量上传。
- 记录链路 B 的吞吐、连接时间、重连时间、丢包和功耗。
- 主机 Wi-Fi 与 BLE 同时工作时，链路 A 的丢帧率和 P95 延迟仍满足指标。

## 5. 对选型的影响

- 探头端：继续优先选择 BLE 5.0、2M PHY、低功耗无线 MCU。
- 主机端：需要具备 BLE 和 Wi-Fi 共存能力，或者使用两个独立无线模块。
- 主机端可以采用较大电池或固定电源，因此 Wi-Fi 的功耗约束比探头端宽松。
- Wi-Fi 芯片至少支持 2.4 GHz；若成本允许，优先选择 2.4/5 GHz 双频，以减少与 BLE 探头的 2.4 GHz 共存压力。

## 6. 链路 A 是否随链路 B 改为 Wi-Fi

不随链路 B 改变。重新比较后的结论是：

| 方案 | 关键数据 | 结论 |
| --- | --- | --- |
| BLE 5.0，2M PHY | 蓝牙 SIG 给出的 2M PHY 理论链路吞吐约 1.58 Mbps | 保留为首选；对 158.4 kbps 需求约有 10 倍余量 |
| ESP-NOW v1/v2 | 公开医疗 IoT 项目加密实测约 280 kbps、平均 RTT 4.14 ms | 只作为两端都使用 Espressif 平台时的原型备选；低于 320 kbps 目标 |
| Nordic ESB | nRF5 间负载 1~252 B，支持 ACK 和自动重传 | 作为需要最低延迟和完全控制协议时的备选 |

链路 B 使用 Wi-Fi 不代表链路 A 也应使用 Wi-Fi。探头仍受功耗、体积和电池
约束，BLE 的独立跳频连接也比 ESP-NOW 与 Wi-Fi 固定信道耦合更容易处理
共存问题。
