## 2. 一条命令重跑

```bash
# 全流程（约 6 s）：解包校验 → 清单 → 划分 → 端点/重采样/带通/切窗/z-score/BER → 写产物
.venv/bin/python tools/preprocess.py all

# 可复现性验收：重跑并比较 5 个产物的 sha256
.venv/bin/python tools/preprocess.py verify

# 机器自检（7 项断言）
.venv/bin/python tools/preprocess.py self-test

# 目视验收图
.venv/bin/python tools/preprocess.py figures

# ADR-036 的证据：带通在 8 kHz 做 vs 在 2 kHz 做
.venv/bin/python tools/preprocess.py probe-filter --n 50
```

依赖：`.venv` 里 `numpy`、`scipy`、`libarchive-c`（rar 读取）、`matplotlib`（仅出图）。
流水线**不含时间戳、不含随机初始化**，`splits.json` 的 `created` 是固定字符串，因此重跑哈希稳定。

## 3. 逐步结果

### 3.1 解包与清单（checklist §1）

- 5 个类别压缩包（GitHub blobs API，见 ADR-035）：**5/5 通过 git blob SHA-1 校验**，与仓库逐字节一致。
- 合计 18,791,415 B（18.8 MB）→ 解包 **40 MB / 1,000 个 wav**。
- 断言：**1,000 条**、**5×200**（AS/MS/MR/MVP/N 各 200）→ 通过。
- 头校验：**1,000/1,000** 为 8 kHz / 单声道 / 16 bit；无失败、无跳过。
- 原始时长 1.156–3.993 s，中位 **2.427 s**（与 `plan-5class-vhd.md` §1 的实测值一致）。

### 3.2 端点检测（checklist §2）

- 25 ms 帧（200 点）/ 10 ms 移（80 点）；短时能量 = 帧均方值；噪声底 = 能量序列 **10 分位**；阈值 = **×3**。
- 结果：**0 条异常**（无 <0.5 s、无全静音、无不可分）。
- 裁掉时长：中位 **0.114 s**，p95 **0.408 s**；保留能量中位 **0.999999**、最小 **0.9914**（最差仅丢 0.86% 能量 → 没有过切）。
- 精度（合成信号，真实起止已知）：起始误差 **20 ms**、结束误差 **15 ms**，均 < 一帧 25 ms。

### 3.3 重采样 2 kHz（checklist §3）

- `resample_poly(up=1, down=4)`，Kaiser 窗 FIR；重采样后长度与 `len/4` 差 **0**。
- 抗混叠（合成 2.6 kHz 单音，抽取后本应折到 600 Hz）：流水线内部区间残余 **-69.1 dB**；直接抽取 `x[::4]` 为 **-0.0 dB**。
- 抗混叠（真实数据）：带通后 8 kHz 信号中 >1.02 kHz 相对 20–1000 Hz 的功率，最差 **-52.5 dB**、中位 **-63.3 dB**（10 条抽样）。
- 真实录音注入 2.6 kHz 单音后，600 Hz 带内增量 **0.00 dB**（无混叠泄漏）。

### 3.4 带通 20–1000 Hz（checklist §4）

- `butter(4, [20, 1000], "bandpass", fs=8000, output="sos")` → **8 极点 / 4 个二阶节**（scipy/MATLAB 的 N=4 带通）；`sosfiltfilt` 零相位（ADR-034）。
- **实现位置改动**（ADR-036）：在 8 kHz 上滤波、再 1/4 抽取。原因：2 kHz 的 Nyquist 正好 1,000 Hz，`butter(..., fs=2000)` 直接 `ValueError`。
- 实测响应：-3 dB 点 **20.02 / 999.45 Hz**；10 Hz **-24.6 dB**；2.6 kHz **-48.3 dB**；3.5 kHz **-87.4 dB**。
- ⚠ **与清单文字不一致（须报告）**：清单 §4 的验收写"确认 **50 Hz 干扰被压**"，但 20 Hz 高通对 50 Hz 的衰减实测 **-0.00 dB**——50 Hz 在通带内，**本流水线不抑制工频**。要压 50 Hz 必须抬高下限（会同时砍掉 20–50 Hz 的心音能量），属于改冻结参数，须另立 ADR。当前做法按 `parameter-ledger.md` 的 20 Hz 不动。

### 3.5 切窗与归一化（checklist §5）

- 2 s（4,000 点）/ 1 s（2,000 点）步进；**尾部未覆盖时补一个尾对齐窗**（ADR-037）。
- **1,791 个窗**（落在验收区间 1,500–2,000）；每条录音：**1 窗 235 条 / 2 窗 739 条 / 3 窗 26 条**（1–3，满足验收）。
- 短于 2 s 的录音（端点检测后 **23.5%**）两端补零；**含补零的窗 235/1,791 = 13.1%**，其中 pad_ratio 中位 **0.0325**、p95 **0.224**、最大 **0.4675**。
- 每窗独立 z-score：实测 |mean| ≤ 1e-6、std ∈ [0.999, 1.001]；**0 个零方差窗**。
- 每类窗数：AS **424**、MS **331**、MR **324**、MVP **374**、N **338**（最大/最小 **1.31×**）。
  原因：AS 录音更长（原始均值 2.74 s vs MR 2.26 s），不是划分偏差。

### 3.6 划分索引（checklist §6）

| 检查 | 标准 | 实测 | 结果 |
| --- | --- | --- | --- |
| 无泄漏 | 任一 recording_id 只出现一次 | 1,000 = unique | ✅ |
| 分层 | 每折每类 34±2；holdout 每类 30±2 | 5 折各 34/类；holdout 30/类 | ✅ |
| 覆盖 | 全部被分配、无遗漏无重复 | 150 + 5×170 = 1,000 | ✅ |
| 可复现 | 同种子重跑完全一致 | 重建 `splits.json` 一致；重跑 5 个产物哈希逐字节一致 | ✅ |
| 窗不跨折 | 窗的 split 必须等于其录音的 split | 1,791 窗，**0 违例** | ✅ |

- seed **42**；holdout **150**（15%，每类 30）；5 折各 **170**（每类 34）。
- `splits.json` 记录 `class_order`、`counts`、`note`（规则与随机方式），便于外部复算。

### 3.7 BER（checklist §7，W1 只算不拒识）

- 定义：目标带 **[20,700) Hz** ÷ 噪声带 **[0,20) + [700,1000) Hz**；Welch（Hann，nperseg 1024，重叠 512）+ 梯形积分。
- **在带通前的 2 kHz 信号上算**（ADR-038）：带通后算会把噪声带本身滤掉，等于测滤波器。两种口径差 **~16 倍**（中位 9,210.7 vs 571.9）。
- 结果：中位 **571.9**；p5 **163.1**、p10 **224.5**、p20 **308.0**、p90 **1,434.3**、p95 **1,940.1**；无 `inf`/`nan`。
- W3 的拒识阈值在这些分位点上取（默认拒 10% → 阈值 ≈ 224），W1 **不拒识**。

## 7. 已知风险与待确认

1. **窗总量与类不均衡**：1.79 窗/条，每类窗数 324–424（1.31×）。窗级 accuracy 会轻微偏向窗多的类；主指标 macro F1（ADR-022/031）可抵消，但**报告里必须给窗数与录音数两张分布表**。
2. **近重复窗**：2.3 s 录音的两窗重叠 80%。划分以录音为单位，不跨折泄漏；窗级指标的乐观偏差由录音级 soft voting + 录音 cluster bootstrap 兜（ADR-031）。若 W2 发现窗级与录音级差 >5 点，按 ADR-037 回退到 1,026/1,291 窗口径并重跑全部臂。
3. **补零 13.1%**：z-score 后补零段是常数 0，模型可能学到"零段"这个伪特征。W3 做质量门时应把 pad_ratio 作为协变量报告；若发现模型对 pad_ratio 敏感，属于新问题（须新 ADR）。
4. **BER 与主观噪声的相关性未验证**：W3 需抽 50 条人工判读，确认"明显噪声录音"确实落在低 BER 端（ADR-038 失败判据）。
5. **`data/` 被 `.gitignore` 整目录忽略**，所以冻结产物**没有进 git**。当前靠"磁盘归档 + SHA-256 + 本报告登记哈希"。
   **待你决定**：是否给 `data/processed/{manifest.csv,windows.csv,quality.csv,splits.json}`（合计约 330 KB）开一条 `.gitignore` 例外，让索引随代码一起提交？我倾向开例外（清单 §10 写的是"提交归档"），但这会改变仓库卫生策略，**不擅自改**。
6. **端点检测的 30 条人工比对**未做（见 §4 最后一行）。
