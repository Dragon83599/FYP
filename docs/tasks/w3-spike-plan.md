
**关键纪律**

## 3. 三轨部署与测量

### 通用测量协议（三轨一致）

| 项 | 要求 |
| --- | --- |
| 预热 | 前 **10 次**丢弃 |
| 重复 | **100 次**，固定输入顺序 |
| 统计 | **中位数 + P95**（不报均值）|
| 日志 | **关闭串口/控制台打印** |
| 记录 | 每次的毫秒数写入 CSV（便于复查）|
| 重复性 | 全部测完后再独立跑一轮，两轮中位差应 **<10%** |

### 轨 ① 手机 PWA

- [ ] 用 `tensorflowjs_converter` 把 Keras/TFLite 模型转成 TF.js 格式
- [ ] 写最小页面：录音（或播放预录 wav）→ 预处理 → 推理 → 显示五类概率
- [ ] **预处理器要用 JS 重写**（重采样、带通、z-score、切窗），并与 Python 版对齐（同一窗的输出差 <1e-3）
- [ ] 记录：**机型、浏览器与版本、WebGL 是否可用、最大纹理尺寸**
- [ ] 测 100 次，分"纯推理"与"端到端（含预处理）"两组

**已知风险**：Chrome on Android 的最大纹理尺寸 **4096**（17）；若模型/输入超限，需缩小输入或换 WASM 后端。

### 轨 ② 树莓派 4B（参考轨，最可能成功）

- [ ] 安装 `tflite-runtime`（或完整 TF）
- [ ] 用 Python 脚本：读 wav → 预处理 → 推理
- [ ] 测 100 次（纯推理 / 端到端）
- [ ] 在 **holdout** 上跑全部窗，算窗级与录音级 macro F1
- [ ] 记录：系统版本、Python 版本、是否开启多线程

### 轨 ③ ESP32-S3（卖点，风险最高）

- [ ] 选择后端：**esp-dl** 或 **TFLite Micro**（看现有工程链）
- [ ] 把 int8 模型转成 C 数组（`xxd -i`）或放进模型分区
- [ ] 固件：从 flash 读预录 wav → 预处理 → 推理 → 串口输出（**测量时关闭**）
- [ ] 测 100 次，记录：
  - [ ] 纯推理时延（中位 + P95）
  - [ ] 端到端时延（含预处理）
  - [ ] **峰值 RAM**（`esp_get_free_heap_size` 差值）
  - [ ] **Flash 占用**（固件 + 模型分区）
- [ ] 在 holdout 上跑全部窗，算精度

**已知风险**：算子不支持（如 tanh/特定 padding）→ 先在 PC 上检查模型算子清单；必要时替换为 GAP 版本。

## 5. 判定规则（spike 结束当场执行）

| 结果 | 结论 |
| --- | --- |
| S3 端到端 **RTF ≤1.2** 且掉点 **≤2 点** | **S3 作部署轨**，三轨全保留 |
| S3 RTF **1.2–1.5** | 保留 S3，论文写"筛查可用、连续监测不可用" |
| S3 RTF **>1.5** 或掉点 **>2 点** | ① 转 QAT 重测；② 仍不行 → 试 A3-1.5s；③ 再不行 → **放弃 S3，保留 PWA + 树莓派** |
| PWA 端到端 **>1 s** | 检查是否误把预处理算进推理、是否 WebGL 未启用 |
| 树莓派都跑不通 | 先查模型算子支持，而不是换板 |

## 7. 不要做的事

| 禁止 | 原因 |
| --- | --- |
| 用 holdout 调量化参数 | 等于用测试集调参（12/16 的错）|
| 只测 1 次就报数 | 首次推理含缓存未命中 |
| 开着串口打印测时延 | I/O 时间会混进推理 |
| 用"平均时延"代替中位/P95 | 长尾被掩盖 |
| 在 spike 阶段改模型结构 | 结构与训练前定死（ADR-026）|
