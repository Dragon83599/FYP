# 工程决策指南

> 适用范围：硬件、软件、协议、算法、云服务、结构、成本和测试方案。

## 1. 决策原则

每个选择都回答同一个问题：

```text
在明确的约束和可验证指标下，哪个方案能以可接受的风险和成本满足需求？
```

禁止使用“更先进”“更方便”“性能更高”作为唯一理由。必须说明相对谁、提升多少、
在哪次测量或哪份资料中得到，以及是否适用于目标硬件和真实环境。

## 2. 最低对比项

| 维度 | 必须回答 |
| --- | --- |
| 功能 | 是否满足二体式、无线、本地 AI、显示、回放和上传需求 |
| 性能 | 吞吐、延迟、采样率、CPU、内存、启动和重连时间 |
| 功耗 | 峰值电流、平均电流、续航和充电要求 |
| 成本 | 单件成本、开发工具、认证、PCB 面积和量产风险 |
| 复杂度 | 驱动、协议栈、配对、调试、维护和团队学习成本 |
| 可靠性 | 丢包、干扰、断线恢复、温度和异常处理 |
| 安全 | 配对、认证、加密、密钥和数据隐私 |
| 供应链 | 库存、交期、停产风险、替代型号和封装 |
| 可测试性 | 是否能测量、复现、记录数据并定义失败判据 |
| 进度 | 对阶段目标、联调和最终演示的风险 |

## 3. 证据等级

| 等级 | 证据 | 可用于最终冻结 |
| --- | --- | --- |
| E1 | 标准、datasheet、官方规范、官方实测 | 是，但仍需目标硬件验证 |
| E2 | 可复现的独立论文或开源实测 | 可作为候选证据，需注明条件 |
| E3 | 厂商宣传或未标注测试条件的性能 | 只能用于筛选，不能独立冻结 |
| E4 | 工程估算、经验或假设 | 只能用于早期方案，不得作为最终依据 |

来源必须记录链接、版本或日期。性能数字必须区分理论值、链路值和应用层值。

## 5. 评分方法

对候选方案按需求加权评分，权重之和为 100。建议权重：

| 指标 | 建议权重 |
| --- | ---: |
| 功能满足 | 25 |
| 性能与可靠性 | 20 |
| 功耗与热设计 | 15 |
| 开发复杂度与进度 | 15 |
| 成本与供应链 | 10 |
| 安全与隐私 | 10 |
| 可测试性与维护 | 5 |

评分不能替代实测。权重和分数必须在决策记录中可见，不能只给总分。

## 6. 组会 PPT 对比结构

每个重大决策使用以下页面，页面数量按复杂度调整：

1. 决策问题与为什么现在要决定。
2. 需求、约束和验收指标。
3. 候选方案总览。
4. 量化对比表。
5. 优缺点、风险和成本。
6. 最终选择与理由。
7. 验证计划、失败判据和回退方案。

PPT 中不能只放最终结论，也不能用“综合考虑”代替数据。
