→ 测试集里几乎必然含有训练集同一段录音的相邻片段。**这是 97–99.7% 最可能的来源。**

## 3. 你计划里的 8 个问题

### P1 特征太多，做不完也说明不了问题
你列了 7 种：STFT、Mel、MFCC、CWT、双谱、DWT、DFT+log。它们其实只有 3 类：

- **二维时频**：STFT / Mel / 对数谱 / CWT / 双谱
- **一维多分辨率**：DWT
- **倒谱**：MFCC

7 × 4 模型 = 28 组实验，时间不够，而且同类特征高度相关，跑完也回答不了"为什么"。

### P2 模型和特征必须配对，不能混着试
- 2D 特征（谱图/双谱/CWT）→ 2D CNN / ResNet / GoogLeNet
- 1D 特征（DWT 系数、原始波形）→ 1D CNN
- **LSTM 是反例**：同一篇论文里 LSTM 93.0%、CNN 99.67%——差 6.7 个点。**建议直接淘汰 LSTM**，并在论文里引用这个对比作为理由。

### P3 "AOCT" 不是标准模型
它只是那篇博客给"4 个卷积块的 CNN"起的名字。你如果写"采用 AOCT"，答辩时会被问"AOCT 的定义、出处、和 ResNet 的区别"——答不上来就扣分。要么画清楚那 4 个块并说明是自己复现，要么直接叫 "4-block CNN"。

### P4 下采样率三个文章不一致（1 kHz vs 8 kHz vs 4 kHz）
- AOCT、1D-CNN+DWT：**1 kHz**（理由：病理心音 <500 Hz）
- 对数谱、ResNet：用原始 8 kHz
- 我们旧流水线：4 kHz

**必须自己定一个并说明理由**。建议：**1 kHz**（带通 25–400 Hz），模型最小、和两篇论文一致；但要注意 **MVP 的收缩期喀喇音频率偏高**，400 Hz 低通可能削弱它——这是你可以做的消融实验（400 Hz vs 800 Hz 截止）。

### P5 部署板和模型不匹配
- Pi Zero **一代**（ARM1176，**无 NEON**）跑 GoogLeNet（约 500 万参数）→ 秒级延迟，不现实。
- 双谱/CWT 的 256×256 2D CNN 在 Pi Zero 一代上也很吃力。
- **1D-CNN + DWT（2942 维输入）最轻**，最适合 Pi Zero 一代或 ESP32-S3。
→ 先确认你的 Zero 是一代还是二代，再定模型。

### P6 评估方式必须改
6 篇全是片段级随机划分。你要做的是：
1. **先按录音分组**（同一段录音的所有片段只进一折）；
2. 报告"随机划分 vs 录音划分"两个数字；
3. 差异就是你的核心发现。

### P7 文献质量
5 篇是知乎博客，其中 3 篇是论文翻译（deephub）。**论文里不能引知乎**，要引原文：

- 1D-CNN+DWT：2022 ICETCI，NIT Rourkela / Central University of Rajasthan（需查准确标题作者）
- 对数谱：deephub 译的那篇原文（需查）
- CWT+GoogLeNet：出处不明
- ResNet / AOCT：**只有博客，没有对应论文**

→ 我能帮你查前两篇的原文；后两篇只能作为"工程参考"，不能当学术依据。

## 4. 建议的最终方案（三臂，够写论文）

| 臂 | 特征 | 模型 | 为什么选它 | 参考 |

**评估**：录音级分层 5 折（主）+ 片段级随机 70/30（对照），报 macro F1、每类 F1、混淆矩阵、bootstrap CI。

**预期结果**：片段级 97–99%，录音级会掉到 85–92%。**这个差距就是论文的核心贡献**，也是"工程师思维"的体现。
