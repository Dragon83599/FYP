## 0. 链路 A 决策基线

本轮先冻结以下候选值。无线模块必须用实测数据证明能够满足这些条件，否则通过
版本升级更换物理层，但 `LKA1` 分包格式不变。

| 决策项 | 候选冻结值 | 验收要求 |
| --- | --- | --- |
| 无线制式 | BLE 5.0 GATT 自定义服务 | 探头为 peripheral，主机为 central；手机侧由主机 Wi-Fi 负责 |
| PHY | 优先 2M PHY，兼容回退 1M PHY | 两者都记录吞吐和延迟 |
| 连接间隔 | 首选 15 ms，最大不超过 30 ms | 同一连接事件尽量发送一帧的两个 notification |
| ATT MTU | 247 B | GATT notification 的 value 最大 244 B |
| `LKA1` 单包上限 | 244 B | `20 B header + 222 B 负载 + 2 B CRC` 不得超过该值 |
| 最大分片负载 | 222 B | `244 - 22 = 222 B` |
| 352 B AUD1 帧分片 | 222 B + 130 B，共 2 包 | 每帧无线包总长约 396 B |
| 应用层吞吐 | 158.4 kbps | 仅计算 `LKA1` 包；不含 BLE 协议开销、重传和连接维护 |
| 持续吞吐要求 | 至少 320 kbps，目标 500 kbps | 为 2 倍吞吐余量预留空间 |
| 链路附加延迟 | P95 <= 15 ms，最大 <= 30 ms | 从完整 20 ms 帧交给无线层开始计时 |
| 端到端采集延迟 | P95 <= 40 ms，最大 <= 60 ms | 从该帧首样本采集时刻到主机完整解码该帧 |
| 重传策略 | 默认使用 BLE 链路层 ACK/重传 | 不默认启用应用层 ACK；可选 NACK 仅重传缺少的分片一次 |
| 丢帧指标 | 重传完成后完整帧丢失率 <= 0.1% | 不能出现连续 3 帧丢失 |
| 安全 | LE Secure Connections + bonding | 探头与主机配对后绑定，禁止长期明文配对模式 |

BLE 链路层已经对数据包进行确认和重传，因此应用层不需要默认把每个分片再 ACK
一次。主机通过 `session_id + frame_sequence + fragment_index` 完成重复包抑制和
缺片统计。若实测发现完整帧丢失率超过指标，再启用可选 NACK：

- 主机在 20 ms 窗口内 NACK 缺失分片。
- 探头最多重传 1 次。
- 重传仍失败则放弃该帧，并记录序号，不得阻塞后续帧。

主机只需要作为 BLE central 连接探头；手机侧使用 Wi-Fi 后，不要求主机同时
担任 BLE peripheral。主机仍需验证 BLE central 与 Wi-Fi station/SoftAP 的
并发共存，但不需要修改 `LKA1` 格式。

## 1. 范围

链路 A 是探头到主机的无线链路。本文件只定义与应用逻辑相关的分包和重组
格式，不规定 BLE、2.4 GHz 私有协议或 Wi-Fi 的物理层细节。

链路 A 传输的完整负载是一个 `AUD1` 应用帧：

```text
30 B header + 320 B PCM + 2 B CRC = 352 B
```

## 2. 三层责任

| 层次 | 本仓库定义 | 硬件/无线模块提供 |
| --- | --- | --- |
| 应用层 | AUD1 帧、`sequence`、`timestamp_ms`、CRC | 无 |
| 链路 A 分包层 | `LKA1` 包、分片、重组、重复包检测 | 单包 MTU 和发送能力 |
| 物理链路层 | 不定义 | BLE、2.4 GHz、Wi-Fi 等无线实现 |

## 3. `LKA1` 固定包格式

所有整数字段为小端。

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | `magic` | ASCII `LKA1` | 固定值 |
| 4 | 1 | `version` | `uint8_t` | 当前为 `1` |
| 5 | 1 | `type` | `uint8_t` | `1=DATA`、`2=ACK`、`3=NACK` |
| 6 | 1 | `flags` | `uint8_t` | bit0 START、bit1 END、bit2 重传 |
| 7 | 1 | `reserved` | `uint8_t` | 必须为 `0` |
| 8 | 2 | `session_id` | `uint16_t` | 一次连接或测量会话编号 |
| 10 | 4 | `frame_sequence` | `uint32_t` | 与 AUD1 `sequence` 相同 |
| 14 | 1 | `fragment_index` | `uint8_t` | 从 `0` 开始 |
| 15 | 1 | `fragment_count` | `uint8_t` | 本帧的分片总数 |
| 16 | 2 | `fragment_offset` | `uint16_t` | 在 352 B 应用帧中的偏移 |
| 18 | 2 | `fragment_bytes` | `uint16_t` | 当前分片的负载长度 |
| 20 | N | `payload` | bytes | 应用帧的一个连续片段 |
| 20+N | 2 | `crc16` | `uint16_t` | 对 header 和 payload 计算 |

固定开销为 `20 B header + 2 B CRC = 22 B`。

BLE ATT MTU 为 247 B 时，GATT notification value 上限为 244 B。扣除
`LKA1` 的 22 B 固定开销后，单分片最大负载为 `244 - 22 = 222 B`。
完整 352 B 帧在默认配置下分为 `222 B + 130 B` 两个分片，对应无线包
`244 B + 152 B = 396 B`。

### 3.1 固定测试向量

测试包参数：

```text
type             = DATA (1)
flags            = START (1)
session_id       = 0x1234
frame_sequence   = 7
fragment_index   = 0
fragment_count   = 2
fragment_offset  = 0
payload          = 00 01 02 03 04 05 06 07 08 09
```

期望的 32 字节 `LKA1` 包：

```text

```

## 4. 分片规则

- 非最后分片长度相同，默认 222 B。
- 第一片设置 START，最后一片设置 END。
- `fragment_offset` 必须连续覆盖 `0..351`，不允许空洞。
- 同一帧的 `fragment_count` 必须一致。
- ACK/NACK 的 fragment 字段全部为 `0`，payload 为空。
- 重复分片必须内容完全一致；不一致时丢弃整帧并报告冲突。
- 一帧必须通过 AUD1 CRC 后才交给显示、回放或 AI。

## 5. 丢包与重连

- 未收到完整分片集的帧不得进入 AI。
- 主机按 `session_id + frame_sequence` 统计丢帧和乱序。
- 新会话开始时更换 `session_id`，防止旧包被误重组。
- 是否 ACK、重传次数和超时策略由无线制式确定，但必须遵守本包格式。
- BLE 或私有协议如果提供可靠传输，可以使用 `type=ACK` 作为应用层确认；
  如果已有可靠链路，也可以先不启用重传，只做统计。

## 6. 无线选型必须返回的数据

- 无线制式、芯片/模块准确型号。
- 可用单包负载或 MTU。
- 实际持续吞吐和 2 倍余量验证结果。
- 平均、P95 和最大延迟。
- 是否自动重传、是否保证顺序。
- 与主机 Wi-Fi 链路同时工作时的干扰和吞吐。
- 探头无线发送所需的供电、体积和功耗。

## 7. 验收测试

- 352 B 帧拆成 2 个分片后能完整重组。
- 逆序到达时仍能完整重组。
- 重复分片不会重复写入。
- 丢失任意一片时不能产生完整帧。
- 修改任意一个无线包字节后 CRC 必须失败。
- 新旧 `session_id` 的包不会混合。
- 连续运行 5 分钟，记录丢帧、延迟和缓冲区峰值。

## 8. 发给硬件队友的确认项

```text
链路 A 我先冻结为以下候选基线，请确认模块和实现是否支持：

1. BLE 5.0 GATT 自定义服务；探头为 peripheral，主机为 central；手机侧走 Wi-Fi。
2. 优先使用 2M PHY，至少支持 1M PHY 回退和数据长度扩展。
3. ATT MTU 协商到 247，GATT notification 负载按 244 B 计算。
4. LKA1 单包不超过 244 B，分片负载不超过 222 B。
5. 完整 352 B AUD1 帧拆成 222 B + 130 B 两包，每帧约 396 B。
6. 持续有效吞吐至少 320 kbps，目标 500 kbps。
7. 连接间隔优先 15 ms，最大不超过 30 ms。
8. 从完整帧交给无线层到主机完整接收，P95 不超过 15 ms，最大不超过 30 ms。
9. 默认使用 BLE 链路层 ACK/重传，不默认增加应用层 ACK。
10. 连续 5 分钟后，重传完成的完整帧丢失率不超过 0.1%，且不能连续丢 3 帧。

请给出无线模块型号、实测 MTU、吞吐、P95/最大延迟、重传行为和两段 2.4 GHz
链路共存结果。若模块不能满足，请直接给出可以满足的替代模块。
```
