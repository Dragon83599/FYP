# 主机资源预算模型（2026-10-18）

> 用途：给 ADR-006（主机平台选型）提供量化输入。**这不是选型结论**，而是一张
> "当前设计需要多少资源"的账，用来判断 ESP32-S3 是否还够、什么条件下必须换平台。
>
> 证据等级：标"实测"的项目来自本机 `idf.py size`（E2/E4）；标"估算"的是工程
> 估算（E4），必须在目标板上复测后才可冻结。

## 1. 实测基线（ESP32-S3，固件 v5.5.6，含心率检测）

| 项 | 字节 | 来源 |
| --- | ---: | --- |
| `.bss` | 82,208 | 实测 |
| `.data` | 16,388 | 实测 |
| DIRAM 已用 / 总量 | 169,979 / 341,760（49.74%） | 实测 |
| **DIRAM 余量** | **171,781** | 实测 |
| Flash Code | 322,056 | 实测 |
| Flash Data | 86,156 | 实测 |
| 镜像总计 | 512,399 | 实测 |
| IRAM | 16,384 / 16,384（**100%**） | 实测 |

`.bss` 的构成：环形缓冲 25,600 + AI 窗口 16,000 + 心率工作缓冲 35,448 + 其他 5,160。

> 注：DIRAM 总量 341,760 B 而非标称 512 KB SRAM，因为一部分被 ROM/cache 占用。
> 预算按 341,760 计算，不能用 512 KB。

## 3. 两种放置策略的结果

| 策略 | 需要 | 余量 171,781 | 结论 |
| --- | ---: | ---: | --- |
| 权重放 RAM | 241,459 | **−69,678** | **放不下** |
| 权重放 flash（`const`，memory-mapped） | 171,008 | **+773** | 勉强放下，**零余量** |

这个结果比"大概够用"有用得多：**ESP32-S3 只有在"模型权重驻留 flash + 激活缓冲尽量
放 PSRAM"的前提下才勉强容得下显示与推理**，任何额外缓冲都会直接构建失败或运行期 OOM。

## 4. 显示方案对平台选择的压力

| 分辨率（RGB565，30 fps） | 帧缓冲 | 带宽 | 判断 |
| --- | ---: | ---: | --- |
| 320×240 | 153,600 B | 4.6 MB/s | 帧缓冲必须放 PSRAM；S3 可行 |
| 480×320 | 307,200 B | 9.2 MB/s | 仍在 PSRAM 能力内，但与 AI 权重争带宽 |
| 800×480 | 768,000 B | 23.0 MB/s | PSRAM 带宽与延迟压力显著，建议评估 ESP32-P4 |

## 5. 判定规则（写死，避免以后凭感觉）

| 条件 | 结论 |
| --- | --- |
| 单色/小尺寸 SPI 屏（≤320×240），权重放 flash | **ESP32-S3 仍可**（余量 ≈0，需实测堆余量） |
| 需要 RGB 并口屏（≥480×320）或双帧缓冲 | 评估 **ESP32-P4 + C6** |
| 模型超过 ~100 KB INT8 或需要 >64 KB 激活 | 评估 **ESP32-P4 + C6** 或更大 RAM 的 MCU |
| 需要 Linux 级 GUI / 多进程 | 评估 Linux SoC（功耗与启动代价最高） |

## 6. 功耗粗算（E4，仅用于容量规划）

| 模式 | 电流（估算） | 说明 |
| --- | ---: | --- |
| 采集 + BLE + 心率 | 60–90 mA | 无屏无 Wi-Fi |
| 加 Wi-Fi 上传 | +80–120 mA（峰值） | 与 BLE 分时共存 |
| 加 3.5" LCD 背光 | +60–100 mA | 背光通常占大头 |
| 峰值估算 | **200–300 mA** | 2,000 mAh 电池约 7–10 h |

必须在目标板上用电流探头实测，本节不能作为续航承诺。

## 7. 上板后必须复测的项

1. `idf.py size` 的 DIRAM 余量，以及运行期 `heap_caps_get_minimum_free_size()`；
2. ESP-DL 推理的真实激活内存（本节用的 32 KB 是估算）；
3. PSRAM 带宽：显示刷新与推理同时进行时是否出现撕裂或推理超时；
4. 显示刷新下的 P95 推理时延（ADR-008 判据：不超过显示周期的 50%）；
5. 功耗：采集 / 加 Wi-Fi / 加背光三种组合的电流。

## 8. 与 ADR-006 的关系

本文只提供预算，不改变 ADR-006 的"待定"状态。它给出的可执行结论是：

- **不要**在没有实测堆余量的情况下直接批准 ESP32-S3 量产；
- 若显示方案升级到 RGB 并口屏，ADR-006 的候选 B（P4+C6）应提前评估；
- 任何"再加一个功能"的提案，都必须先回到第 3 节的余量数字。
