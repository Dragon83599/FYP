## 方法

### 深度学习路线（主打）

- 预处理：**标准化** `x_new = (x - μ) / σ`（原文式 (1)，只说 "signal normalization"，**没写 z-score 这个词**；和我们 plan 的 z-score 形式相同）
- 特征表示：**CWT（Morse 小波）** → scalogram → 缩放成 **224×224×3** RGB
- 模型：**GoogLeNet（Inception）迁移学习**，22 层 / 9 个 inception 模块
- 训练：dropout **0.6**、输出层改 5 类、lr **0.0001**、batch **15**、**20 epochs**、SGD + momentum

### 传统路线（对照）

- 手工特征 **26 维**：10 个时域（RMS、shape factor、偏度、峰度、峰值、impulse/crest/clearance factor 等）+ 16 个频域（SNR、SINAD、THD、**MFCC 13 维**等）
- 特征选择后接 **WKNN**（加权 KNN，权重 `1/d`）

## 第 3 节（方法）详解（2026-10-26）

这一节其实是**两条并行的路线**：深度路线（CWT 图 → GoogLeNet）与传统路线（26 维手工特征 → WKNN），最后比一比。作者想说明"图上深度学习比手工特征强"。

### 3.1 深度路线：把一维心音变成图片

**(a) 为什么必须转成图片**：GoogLeNet 是 ImageNet 出来的图像分类网络，输入固定 **224×224×3**。心音是一维序列，所以要先变成"图"。

**(b) 预处理两步**

1. **标准化（原文式 (1)，未用 "z-score" 一词）**：`x_new = (x - μ) / σ`。原文原话是 `signal normalization has been done using equation (1), where μ and σ is the mean and standard deviation of the signal`。目的：不同录音音量不同，CWT 的幅度会跟着变，标准化后各样本的尺度才可比。
2. **CWT + Morse 小波**：用一组"缩放+平移"的小波去卷信号，得到 **scalogram**（时频图，颜色 = 该时刻该频率的能量）。Morse 小波有两个关键参数（对称性 γ、时间带宽积 β）——**原文一个都没给**。

**(c) 变成 224×224×3**：把 scalogram 缩放成 224×224，再凑成 3 通道。**怎么凑的（复制三份？伪彩色映射？）原文没写**——这是复现的一个洞。

**(d) 划分**：1,000 条 → **800 训练 / 200 验证**。原文只有这两部分，**没有独立测试集**。

### 3.1.2 GoogLeNet 怎么改

原版：22 层、9 个 Inception 模块，输出 1,000 类。作者的改动只有三处：

| 改动 | 内容 |
| --- | --- |
| dropout | 最后一个 dropout 层设为 **0.6** |
| 全连接层 `loss3-classifier` | 输出改成 **5** |
| 输出层 | 换成 classification 层 |

训练：lr **1e-4**、batch **15**、**20 epochs**、**SGD + momentum**。

⚠️ **冻结策略没写**：它说 "tuned some parameters of a few layers"，但到底冻结了前面几层、还是全网微调，原文没说。这直接决定"迁移学习"到底迁了什么。

### 3.2 传统路线：26 维手工特征 + WKNN

**特征（26 维）**

- **时域 10 个**：RMS、shape factor、偏度、峰度、峰值、impulse factor、crest factor、clearance factor 等；
- **频域 16 个**：SNR、SINAD、THD，以及 **13 维 MFCC**（Hanning 窗 → FFT → mel 滤波器组 → 取对数 → DCT）。

**特征选择**：用**卡方检验**算每个特征与类别的显著性，定义 **importance = -ln(p)**；取 **p 最小（score 最高）的 15 个**。原文强调重要性前 10 的特征和箱线图（Fig. 5–6）分布差异明显。

⚠️ 卡方检验要求**离散/分箱**数据，而这里的特征是连续的——**怎么分箱原文没写**。

**分类器**：**WKNN**（加权 KNN），邻居数 **K=5**，权重 `1/d`（距离越近权重越大）。设计意图：缓解"多数类邻居占优"的问题。

### 3.3 评估指标（这里有个坑）

原文 Eq. 6 给的是：

| 指标 | 原文给的公式 |
| --- | --- |
| Accuracy | (TP + TN) / (TP + TN + FP + FN) |
| Sensitivity | TP / (TP + FN) |
| Specificity | TN / (TN + FP) |
| F1 | 2 x Specificity x Sensitivity / (Specificity + Sensitivity) |

⚠️ **它的 F1 用的是"特异度与敏感度的调和平均"，不是通常的 precision/recall F1**。这意味着：**这篇报的 F1 不能和别人的 F1 横比**，只能和同样定义的比。写论文引用它的 F1 时必须说明。

### 3.4 诊断系统

- **采集模块**：自制——胸件 + 橡胶管 + 3.5 mm 麦克风，接电脑；
- **软件**：**MATLAB GUI** 打包成 **EXE**，Windows 上可脱离 MATLAB 运行；
- 推理流程：选音频 → 显示波形 → 点"诊断" → **重采样到 8 kHz**（与训练一致）→ CWT → GoogLeNet → 显示结果。

### 方法层面的四个疑点（复现/引用时注意）

1. **没有独立测试集**：200 条"验证集"既调参又报结果。
2. **Morse 小波参数缺失**、**224×224×3 的三通道来历缺失**。
3. **迁移学习的冻结策略缺失**。
4. **F1 定义非标准**（用特异度而非精确率）。

- 合计：**10 时域 + 3 频谱质量 + 13 MFCC = 26**。也就是说，**一半的特征其实是 MFCC**。
- 原文给的定义（节选）：RMS 是均方；shape factor = RMS / 平均绝对值；impulse factor = 峰值 / 平均绝对值；crest factor = 峰值 / RMS；clearance factor = 峰值 /（平均 √|x| 的平方）。

### 借鉴时的三点注意

1. **特征几乎都是"信号统计量"**，没有用到 S1/S2 分割，也不需要训练——**端侧实现很便宜**（RMS/Std/偏度/峰度都是一次遍历）。
2. **SNR/SINAD/THD 需要先定义"噪声"**：原文写 `noise is measured by the RMS value`（用 RMS 当噪声），这个定义本身有歧义，复现时要自己定。
3. **MFCC 占 13/26**：如果我们的 A1 已经算了 MFCC，那这篇的"增量"其实只有 10 个时域统计量 + 3 个质量指标，**借鉴成本很低**。

### 2026-10-26 你的理解与疑问

> 12这个文献我的理解：文章使用了GoogLeNet和26 维手工特征 + WKNN两条路线，这里有一个疑问GooleNet不需要特征提取吗？两者从结果上看GoogLeNet性能略优于WKNN，那如果考虑到部署到边缘端GoogLeNet还可以这么优秀吗

**逐字保留，未改写。** 三处回应：

**（1）两条路线——对。**

**（2）"GoogLeNet 不需要特征提取"——不对，它只是把特征提取换了位置。**

| 路线 | 表示从哪来 | 分类器 |
| --- | --- | --- |
| 传统 | **人设计**的 26 维统计量 | WKNN |
| 深度 | **人设计**的 CWT 时频图，再让 CNN 学表示 | GoogLeNet |

- CWT 是**固定变换**，参数（Morse 小波）由人选，不是学出来的；
- 真正"自动"的是 CNN 在图上提特征；
- 而且它还用了 **ImageNet 预训练权重**——等于借了别人学好的特征。

所以准确说法：**这条路线没有"手工特征工程"，但仍然有"固定的特征表示"（CWT）和"迁移来的特征"（ImageNet）**。

**（3）"边缘端还能这么优秀吗"——不能，差着两三个数量级。**

- GoogLeNet（CVPR 2015 版）：约 **680 万参数**、224×224 输入约 **14 亿次乘加**；第一层卷积输出就有 112×112×64 ≈ **80 万个元素**（float32 约 3.2 MB）。
- ESP32-S3：240 MHz、512 KB SRAM（可外挂 PSRAM）、无大算力 NPU。**光第一层激活就超过片上内存**。
- WKNN：26 维 × 1,000 个训练样本 = **2.6 万次距离计算**，模型存储约 104 KB（float32）或 26 KB（int8）。

（上面的参数量/FLOPs 是 GoogLeNet 公开规格，不是 Ding 原文；ESP32-S3 的结论是工程估算 E4，**未实测**。）

**（4）"略优"这个说法也要限定。**

- 98.75% 是**四类 VHD 的平均**（不是 overall 97.5%），94.63% 是 WKNN 的四类平均；
- 差距 4.1 个百分点，落在 **200 条验证集**上约等于 **8 条样本**；
- 两组都没有置信区间，**"略优"没有统计支撑**。
