## 结果

### 精度

| 协议 | PhysioNet（二分类）|
| --- | --- |
| **LOOCV** | **91.87%** |
| **10 折 CV** | **93.94%** |

- 与最强基线 **ResNet-18** 比：10 折 **+2.32 点**、LOOCV **+3.31 点**，而 **FLOPs 少 487 倍、参数少 577 倍**
- 去掉物理约束后仍有 91.05 / 88.31% → **物理约束贡献约 2–3 点**
- **跨数据集**：84.35% ± 3.48% 与 80.91%

### 端上部署（**nRF52840，Cortex-M4，TFLM，int8 PTQ**）

| 项 | 数值 |
| --- | --- |
| 量化前 → 后 精度 | **91.87% → 90.91%**（**掉 0.96 点**）|
| 量化前 → 后 时延 | 7.62 ms → **5.31 ms** |
| 量化前 → 后 能耗 | 84.5 µJ → **58.9 µJ** |
| 计算量 | **339.8 kcycles/次** |
| 对比 | 比 LeNet-5 / MobileNetV3 / ResNet-18 **时延与能耗都最低** |
| 全流程 | **采集 → 降噪 → SST 谱图 → 推理，全部在 MCU 内** |

## 与我的 FYP 的关系

**四条结论，其中两条推翻了我之前的判断**：

1. **nRF52840（Cortex-M4、256 KB RAM）能跑心音分类，5.31 ms** —— 我此前以"M3 算力不足"把 nRF52840 淘汰，**这条理由不成立**（它跑的是很小的 TinyPINN，但已证明 M4 级可行）；
2. **PTQ 掉点 <1 点**（91.87→90.91），与 37 的结论一致 → 支持我们"先 PTQ"；
3. **全流程在 MCU 上**（含 SST 谱图）—— 说明"预处理也放端上"是可行的，不一定需要 SBC；
4. **它诚实标注了"未做患者级隔离"** —— 这正是我们 ADR-031 要解决的问题，可作为论文里"别人也承认这个限制"的引用。

**对我们的直接含义**：
- **MCU 层级不是"只能跑 27 那种 1.58 s"**：43 证明 5 ms 级可行（模型更小、输入 1 kHz）；
- **我们的 A3（39.6k 参数 / 8M MACs）比 TinyPINN 大得多**，在 nRF52840 上可能跑不到毫秒级，但**在 S3/P4 上应无压力**；
- **SST 谱图 + 物理约束**是值得记录的建模思路（我们暂不采用，成本高）。
