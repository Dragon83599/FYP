## 数据

- **数据集 1：PhysioNet/CinC2016**——3,240 条，2 kHz，5–150 s，**二分类**（正常/异常）
- **数据集 2：Yaseen**——1,000 条，5 类各 200，约 3 s，8 kHz，含三个心动周期
- 划分：按原始设定（数据集 2 的五类测试样本数为 AS 187 / MR 196 / MS 173 / MVP 163 / N 180）

## 预处理

1. **重采样到 1 kHz**
2. **3 阶 Butterworth 带通 20–400 Hz**
3. 用 **Springer 分割算法**切成 **1.5 s** 段

## 方法

- **端到端**：原始波形直接进网络，无手工特征
- 核心手段：**分组卷积（group convolution）**——原文算过，在 k1=3、b=64、a=16 时，参数只有普通卷积的 **38.1%**、FLOPs 只有 **11.7%**
- 损失：**平衡交叉熵（BCE）**，针对数据集 1 的类别不平衡
- 规模：**52.67k 参数 / 1.59M FLOPs**

## 逐节跟读（2026-10-28）

### 第 1 站：它要解决什么问题（p1）

> `the models have a sizeable computational complexity, which is not suitable for wearable devices`

- 目标：**52.67k 参数 / 1.59M FLOPs**，能跑在可穿戴设备上；
- 注意它不是"再刷一个 SOTA"，而是**在固定算力下做分类**。

### 第 2 站：数据与预处理（p3–4）

- 两个数据集：**PhysioNet2016（二分类）** 与 **Yaseen（五分类）**
- 预处理三步：
  1. **重采样到 1 kHz**
  2. **3 阶 Butterworth 带通 20–400 Hz**
  3. **Springer 分割算法**切成 **1.5 s** 段
- 推算输入：1.5 s × 1 kHz ≈ **1,500 点**（原文未明写点数）

**要想一下**：它**没有回避 S1/S2 分割**，而是用了标准 HSMM 分割——和我们"不分割"的路线相反。

### 第 3 站：模型（p5–7）

```
输入（约 1500 点）
 → 32 通道 3×3 卷积 + 2×2 最大池化
 → 若干 GCT 块（分组卷积）
 → ECA 通道注意力
 → 全局平均池化（GAP）
 → 全连接 → softmax
```

**GCT 块的四步**（这是全文最有技术含量的地方）：

1. **depthwise 卷积**（逐通道）
2. **最大池化** ← **注意：池化放在 depthwise 和 pointwise 之间**
3. **pointwise 卷积（1×1）**
4. **拼接**

**为什么把池化挪到中间？** 原文说：pointwise 卷积本身也含冗余信息，**先池化再 1×1** 能进一步省计算——这是它相对 MobileNet 的小改动。

- 正则：每个卷积模块后 **dropout**、FC 前 **BN**、Softmax 前 **L2**
- 优化：**Adam，lr = 0.0008**

## 继续跟读：结果、对比与坦白（2026-10-28，第 8–12 站）

### 第 8 站：二分类的"敏感度反而更低"（p9）

> `the sensitivity is lower than the baseline`

- 与基线比：准确率 +2.9%、特异度 +3.0%、F1 +0.3%，**但敏感度更低**；
- 作者的归因：**训练集极度不平衡**（PhysioNet 正常:异常 ≈ 4:1），测试集负样本占比高 → 正类被压。

**这就是"加了个好指标，牺牲了另一个"**：只看准确率会以为它全面更好。

### 第 9 站：复杂度对比的完整说法（p10）

- 相比基线：**Macc 提升 1.7%**，而**参数只用基线的 29.36%、运算只用 45.34%**；
- **但它自己承认**：Macc 仍比文献 [13] **低 7%**，因为 [13] 用的是 **2-D 特征**（学习能力更强）。

→ 换句话说：**它是"性价比"赢，不是"精度"赢。**

### 第 10 站：真机续航的真实数字（p12）

| 场景 | 电流 | 300 mAh 续航 |
| --- | --- | --- |
| **连续分类** | **66.2 mA** | **约 4.5 h** |
| 仅采集 | — | 约 8.5 h |

（我上一轮按"每 3 s 一次"算出的 8.6 h，对应的是**间歇分类**；两种口径不矛盾。）

### 第 11 站：最重要的一句坦白（p12）

> `we have had to simplify the proposed model, since it has a large LSTM layer and convolutional layers, which cannot be deployed directly on hardware devices`

**上板跑的不是论文里那个模型，是简化版**（LSTM 太大、放不下）。

→ 这解释了设备端为什么掉 **3.3 / 3.8 个点**——**不是量化误差，是模型被裁剪了**。

**这条对我们极其重要**：如果我们也打算"先训大模型再上板"，就必须报告**上板版本的精度**，而不是训练版本的。

### 第 12 站：结论与后续

- 结论：低功耗 PCG 传感器 + 轻量端到端模型，**可直接部署**在算力受限的传感器上；
- 后续工作：提升传感器性能（没有提"更大数据集"或"临床验证"）。

- **2026-10-28，你的判断（原话）**：> 训练前就把模型结构定死
  - 含义：**不采用"先训大模型、再裁剪上板"**的路线；训练的就是最终要部署的结构；
  - 影响：27 那 3.3/3.8 点的掉落**不会在我们身上发生**（因为我们不换模型），代价是**搜索空间受限**；
  - 边界：**结构定死 ≠ 精度不能变**——量化仍可做，但必须在训练时就模拟（QAT），且上板精度要单独报。


- **2026-10-28，你读完后的判断（原话）**：> 我觉得算（指 1.58 s 处理 1.5 s 音频算实时）
- 我的核算（E4）：
  - **实时因子 RTF = 1.58 / 1.5 ≈ 1.05** —— 处理速度**略慢于**音频到达速度，属于"勉强跟得上"；
  - 若 1.58 s **不含** 1.5 s 采集时间，则**端到端时延 ≈ 3.08 s**（从开始录音到出结果）；
  - 若含采集，则它是真正的流式处理。
- 能耗推算（E4）：245.1 mW × 1.58 s ≈ **0.387 J/次**；300 mAh @3.7 V ≈ 3,996 J → **约 1.03 万次分类**；按每 3 s 一次 ≈ **8.6 小时**连续工作。
- 结论：**用作"筛查"可以接受**；**用作"连续监测"则偏紧**（RTF>1 意味着不能并行处理多段音频）。

### 三处存疑

1. **"Macc" 一词两用**：一处指 **MACs（1.6M 乘加）**，另一处当指标用（"Macc improving by 1.7%"）——引用时必须写清含义。

## 与我的 FYP 的关系

- **这是目前唯一同时给出"Yaseen 五分类 + 参数量 + MCU 型号 + 功耗 + 时延 + 设备端准确率"的公开工作**，比 20（CardioXNet 只报桌面时延）和 26（Lai 用树莓派）都更贴近我们。
- 直接可用的数字：
  1. **52.67k 参数** → 我们 ≤150k 的预算完全容得下，而且它还有余量做更深的模型；
  2. **STM32F405（192 KB SRAM）能跑** → 我们 **ESP32-S3（512 KB SRAM、240 MHz）** 的余量更大；
  3. **设备端掉 3.3–3.8 个点** → 提醒我们"上板后的精度"必须单独报，不能拿 PC 上的数字交差；
  4. **245 mW / 1.58 s** → 时延偏大（1.58 s 对"实时"是勉强），我们若追求 <150 ms，需要比他更小的模型或更快的推理后端。
- 可借鉴的做法：
  - **1 kHz + 20–400 Hz + 1.5 s**：比我们的 4 kHz + 20–1000 Hz + 2 s 更激进，值得作为 A3 的对照配置；
  - **分组卷积**：参数量与 FLOPs 双降，比砍层数有效；
  - **Springer 分割**：它没有回避分割，而是用标准 HSMM 分割——这与我们 plan 里"不做 S1/S2 分割"是两种路线，可以作为对照讨论。
- 需要警惕：
  - **1.58 s/样本**：按"每 1.5 s 音频"算，等于**实时性勉强**；若我们的目标是连续监测，这个数字不达标；
  - **设备端只测了 200 / 50 个样本**，统计意义有限；
  - 数据集 2 的 99.4% 是随机划分下的结果（无患者 ID），和 01/03/17 一样有"数据集内虚高"的问题。
