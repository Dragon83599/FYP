# 40 · FPGA 层级：两篇（2019 诊断 / 2024 分割）

> 阅读深度：**摘要级**。**更正我此前"FPGA 在 PCG 上没有分类"的错误结论。**
> 结论：FPGA 在 PCG 上**有**工作，但**主要在分割与前端**，纯分类只有 2019 一篇。

## 40.1 · 2019 · Real-Time PCG Diagnosis Using FPGA

- 出处：Springer 会议章（DOI: 10.1007/978-3-030-16657-1_48）
- 硬件：**Altera DE2 Cyclone II** FPGA + NIOS II 软核
- 方法：**离散小波变换（DWT）**
- 原文主张：多数 PCG 分割算法"fail to diagnose in real time"，本文用 FPGA 加速处理

**判断**：这是**FPGA 上做实时 PCG 诊断**（DWT 路线），是 FPGA 层级的唯一分类/诊断证据。但：
- 2019 年、DE2 老平台；
- 摘要未给精度与延迟数字（待查证）。

## 40.2 · 2024 · Low-Cost FPGA Implementation of DL-Based Heart Sound Segmentation

- 出处：**IEEE TIM 2024**（DOI: 10.1109/tim.2024.3392271）
- 内容：把 **U-Net 分割**算法优化到低成本 FPGA，用**低分辨率定点数**
- 目标：从听诊器采集到 CVD 检测的**实时响应**

**判断**：FPGA 上的**分割**（不是分类）——说明 FPGA 的用武之地是"把前端算得快"，而不是"跑分类器"。

## 与我的 FYP 的关系

1. **FPGA 层级存在**，但对我们的四周期限不现实（开发周期数月）——M7 门槛仍然成立；
2. **印证一个规律**：越靠近硬件，越倾向于把**分割/前端**硬化，把**分类**留给软件——因为我们这类小模型（几十 kB）软件跑得动；
3. 论文里可以写："FPGA 方案集中在分割与前端加速（2019、2024），分类仍以 CPU/MCU 为主。"
