## 数据与方法

| 项 | 内容 |
| --- | --- |
| 数据 1 | **自采手机心音**（内置麦克风）|
| 数据 2 | PhysioNet/CinC 2016（**二分类**）|
| 数据 3 | **Yaseen 五分类**（每类 200 条、**每条 2 s**、8 kHz）|
| 划分 | **5 折交叉验证，每次训练 80% / 测试 20%** → **随机划分，无录音分组** |
| 预处理 | **两级自适应阈值滤波**（去环境噪声）|
| 模型 | **MBCF-Net**：三个分支（1-D CNN 等）× 各 9 层、核 3，多域特征融合 + 通道增强 |
| 训练 | batch 128、100 epochs、Adam |

## 结果

| 数据集 | 准确率 |
| --- | --- |
| 自采手机数据 | **99.63%** |
| PhysioNet 2016（二分类）| **98.18%** |
| **Yaseen 五分类** | **99.88%**（比最佳基线仅高 **0.08 点**）|

| 硬件 | 时延 |
| --- | --- |
| RTX 3080（10 GB）| **0.1812 s** |
| RTX 4050（6 GB）| **0.2696 s** |

→ **没有手机端推理数据**。原文明确写这是在两块 GPU 上做的 "processing latency study"。

## 与我的 FYP 的关系

**三条判断**：

1. **它不能算"手机端侧部署"**——采集在手机，推理在 GPU。我此前把它列入"手机层级"是**归类错误**，已在全景表更正；
2. **它的 99.88% 是随机 5 折**（无录音分组、无患者信息），与我们 ADR-031 的口径不同，**不可直接比**；
3. **它比最佳基线只高 0.08 点**，但**参数量/GFLOPs 更高**——原文自己承认"优先精度、牺牲算力"。对我们是**反面参考**：端侧不该这么做。

**可借的一点**：**两级滤波**（自适应阈值）用于手机录音降噪——这是我们手机轨可以参考的预处理细节。
