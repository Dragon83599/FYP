## 数据

- **主数据集：Yaseen（文中称 "Github PCG database"）**——5 类：N / AS / MS / MR / MVP
- 次数据集：**PhysioNet/CinC2016**（二分类）
- 合并数据集：Github + PhysioNet
- 划分：**10 折交叉验证**；无患者 ID（Yaseen 本身没有）
- 输入：**原始 PCG 信号**（不分割、不做手工特征、不做增强）

## 方法

两阶段 CRNN：

1. **表示学习（representation learning）**：三条**并行 CNN 通路**
   - 自适应特征提取器（adaptive feature extractor）
   - 频率特征提取器（frequency feature extractor）
   - 模式提取器（pattern extractor）
   - 用 **2D-CNN 的 squeeze-expansion** 结构，获得不同感受野
2. **序列残差学习（sequence residual learning）**：**双向 LSTM + 跳连**

设计目标：端到端、无手工特征、参数少。

### 读的时候问自己三个问题

1. **为什么用三条并行通路**，而不是一条更深的 CNN？（提示：不同感受野抓不同尺度的心音成分）
2. **7.96 MB 对我们意味着什么**？（ESP32-S3 的 SRAM 只有 512 KB → 必须外挂 PSRAM，这算不算"端侧"？）
3. **54.6 ms 是在什么硬件上测的**？（原文只说 benchmarking，**没写平台**——这是它的一个洞）

### 读完你应该能说出

> CardioXNet 用"原始 PCG → 三条并行 CNN → BiLSTM"做五分类，在 Yaseen 上 99.6%，参数量 0.67M、体积 7.96 MB、时延 54.6 ms；它的"轻量"是相对 VGG 级模型，**对 MCU 仍偏重**；而且它自己承认数据缺少患者独立性。

## 逐节跟读（2026-10-28）

### 第 1 站：预处理（p4）——**先看这一句**

> `All the PCG signals are resampled at 2 kHz`

- 原始 Yaseen 是 8 kHz，它**降到 2 kHz**，理由是"保留重要心音成分 + 降低计算量"；
- PhysioNet 那边**只取前 1.125 s**（为了与主数据集时长对齐）。

**要想一下**：2 kHz 的奈奎斯特上限是 1 kHz，而心音杂音的能量主要在 100–600 Hz——**够用**。我们计划的 4 kHz 是它的两倍，属于保守选择。

### 第 2 站：表示学习（p6–7）——三条并行通路

| 通路 | 结构 | 设计意图 |
| --- | --- | --- |
| **FFE**（频率特征提取器）| 4 个 1D 卷积 + 2 个池化；**首层滤波器长度 = Fs×4、步长 = Fs/2** | **大核 + 大步长** → 抓低频、宽频带的成分 |
| **PE**（模式提取器）| 同样是 4 个 1D 卷积 + 2 个池化；但**滤波器 = Fs/2、步长 = Fs/16** | **小核 + 小步长** → 抓细粒度的时间模式 |
| **AFE**（自适应特征增强器）| 输入**reshape 成 2D** → 2D 卷积 + BN + 池化 + **Fire 模块（squeeze-expansion）** | 用 SqueezeNet 的思路**压参数**，同时抓二维纹理 |

三路输出**拼接**（Eq. 13）后进入下一阶段。

**这就是"为什么三条"的答案**：不同感受野——大核看整体频带、小核看细节、2D 路看时频纹理。

### 第 3 站：序列残差学习（p7）

- **两层 BiLSTM** + **跳连**：跳连把 CNN 特征直接加到 LSTM 输出上；
- 目的：既拿时序信息，又不丢 CNN 已提好的特征。

## 我认为重要的点（原话/你的理解）

- **2026-10-28，你读完后的判断（原话）**：> 更差，因为一条永远只能看一个东西
- 方向对，措辞需要修正：**不是"只能看一个东西"，而是"只能在同一尺度上看很多个东西"**。
  - 单条 CNN 每层有几十个滤波器，能看"很多东西"，但它们**共享同一个核大小**（同一个感受野）；
  - 三条并行的关键不是"看得更多"，而是"**尺度不同**"：大核看整体频带、小核看细节、2D 看时频纹理；
  - 一条更宽的路 = **同一尺度**看得更细；一条更深的路 = **尺度逐层变大但细节被压缩**。两者都不是"多尺度并行"。
- 注意：作者**没有做这个消融**，所以"三通路更好"目前是**机理解释**，不是实验结论（E4）。

## 与我的 FYP 的关系

- **它是最接近我们目标的公开参照**：Yaseen、五分类、原始波形端到端、参数/FLOPs/体积/时延**全都报了**。
- 但**"轻量"是相对的**：

| 项 | CardioXNet | 我们（ADR-020/023 预算）|
| --- | --- | --- |
| 参数 | **0.67 M** | ≤ 150k（约 1/4.5）|
| 模型体积 | **7.96 MB** | 分区内（远小于此）|
| 时延 | 54.6 ms（未说明硬件）| 目标 <150 ms（S3）|

→ 它证明了"Yaseen 五分类可以端到端做"，但**没有证明"能上 MCU"**。7.96 MB 对 ESP32-S3 意味着必须外挂 PSRAM。

- 可借鉴：
  1. **三通路并行 CNN**（不同感受野）——比单通路更能抓不同尺度的杂音；
  2. **BiLSTM + 跳连** 做序列建模；
  3. **它报了完整的计算开销表**——我们论文里也应该有这一栏。
- 不能用的：
  - **99.6% 不能当"我们的天花板"**：10 折随机划分、无患者分组；
  - 它的 7.96 MB 与 0.67M 参数**超出我们的预算**；
  - 04 未收录，不能通过 04 引用它。
