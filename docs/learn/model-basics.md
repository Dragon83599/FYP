# 模型结构零基础入门（用我们自己的三个臂讲）

> 目标：看完能说清"我们的模型长什么样、每一层在干什么、数据形状怎么变"。
> 不需要数学；只需要会看"形状"。

---

## 0. 先建立一个直觉

模型做的事：**输入一段数字 → 输出五个概率**。

```
输入：4,000 个数字（2 s × 2 kHz 的波形）
  ↓ 一层层变换
输出：[0.02, 0.91, 0.03, 0.02, 0.02]
        N    AS    MS    MR   MVP   ← 加起来 = 1
```

中间那些"层"，就是**不断改变数据的形状和表示**。我们要认识的就三种：
**卷积层、池化层、全连接层**。

---

## 0.5 先认识 FC（全连接层）

**FC = Fully Connected = 全连接层**。它是"评委"：把前面提好的一堆数字，变成最终的类别分数。

### 它是怎么算的

```
输入 3 个数：[a, b, c]
FC 输出 2 个数：
   y1 = w11·a + w12·b + w13·c + b1
   y2 = w21·a + w22·b + w23·c + b2
```

**"全连接"的意思**：输入的**每一个**数，都要和输出的**每一个**数连一条线（一个权重）。
3 个输入 × 2 个输出 = 6 个权重，再加 2 个偏置 → **8 个参数**。

```
a ──┬──→ y1
b ──┼──→ y1
c ──┴──→ y1
（每个输入都连到每个输出 → "全"连接）
```

### 我们的模型里 FC 在哪

| 模型 | FC 层 | 参数量 |
| --- | --- | --- |
| A3 | 248 → 128 | 248×128 + 128 = **31,872** |
| A3 | 128 → 5 | 128×5 + 5 = **645** |
| A2 | 32 → 5 | 32×5 + 5 = **165** |

### 为什么 FC 最贵

因为它是**输入数 × 输出数**：

| 输入 | 输出 | 权重个数 |
| --- | --- | --- |
| 248 | 128 | **31,744** |
| 3,968 | 128 | **507,904** |

**输入翻 16 倍，权重就翻 16 倍**——没有"共享"。

### 和卷积的区别

| | 卷积 | FC |
| --- | --- | --- |
| 连接 | 只看局部窗口 | 全连 |
| 权重 | **同一组核在整段上复用**（共享）| 每对连接一个权重（不共享）|
| 参数 | 少 | 多 |

这就是为什么"少用 FC、多用卷积/GAP"能大幅省参数。

### 历史上的教训

VGG16 有 1.38 亿参数，其中**第一层 FC 就占了约 1.03 亿**（25,088 × 4,096）——一个 FC 层比整个卷积主干还大。
后来的轻量模型（SqueezeNet、MobileNet）都尽量用 GAP 替代它。

## 1. 三种基本零件

### 1.1 卷积层（Conv）：滑动的小窗口

**做什么**：拿一个固定大小的小窗口（叫**卷积核**），在输入上从左到右滑动，每滑一次算一个"匹配分数"。

```
输入（一维波形，简化成 10 个点）：
  1  3  5  2  0  4  6  1  2  3

核（长度 3）：[1, 0, -1]   ← 它的作用是"看有没有上升沿"

滑过位置 1：1×1 + 3×0 + 5×(-1) = -4
滑过位置 2：3×1 + 5×0 + 2×(-1) = 1
...
```

**关键概念**（只需要记住三个）：

| 概念 | 通俗解释 | 我们的取值 |
| --- | --- | --- |
| **核大小（kernel）** | 窗口有多宽 | 1D：**40 点**（=20 ms）；2D：**3×3** |
| **步长（stride）** | 每次滑多远 | A3 是 1（逐点滑）|
| **通道数（filters）** | **同时用几个不同的核** | 16 → 8 → 4 |

**为什么会有多个通道**：一个核只能学一种模式（比如"上升沿"），多个核就能同时学"上升沿""下降沿""持续高能量"等——每个核产出一张"特征图"。

### 1.2 池化层（Pool）：每几个数里挑一个代表

**做什么**：把相邻的 4 个数压成 1 个（取最大或平均），使序列变短。

```
[1, 5, 3, 2, 8, 4, 6, 0]  --每4个取最大-->  [5, 8]
```

**为什么需要**：① 序列太长算不动；② 让特征对"位置微移"不敏感（心音起点稍偏不影响）。

**我们的取值**：A3 池化 **4**（每层把长度除以 4）。

### 1.3 全连接层（FC）：把特征映射到类别

**做什么**：把前面提取的几十/几百个数，加权求和成 5 个数（五类的分数）。

```
[0.3, 0.9, 0.1, ...] （64 个数） × 权重矩阵 → [分数_N, 分数_AS, ..., 分数_MVP]
```

**它是最"占参数"的部分**：64 个数 → 5 类只需要 325 个参数；但如果前面是 248 个数接 128 个隐藏单元，就有 31,872 个参数——**A3 的 80% 参数都在这里**。

### 1.4 还有两个常用件

| 零件 | 作用 | 我们的用法 |
| --- | --- | --- |
| **激活函数**（ReLU / tanh）| 给网络"非线性"，否则多层等价于一层 | 2D 用 ReLU；1D 照 17 用 **tanh** |
| **BatchNorm** | 把每层输出标准化，训练更稳 | 2D CNN 每层后都加 |
| **Dropout** | 训练时随机关掉一部分神经元，防过拟合 | 0.3 |
| **Softmax** | 把 5 个分数变成"和为 1 的概率" | 最后一层 |

## 2. 看我们的 A3（1D CNN）——完整数据流

输入：**4,000 个点**（2 s @ 2 kHz）

| 步骤 | 操作 | 输出形状 | 参数 |
| --- | --- | --- | --- |
| ① | Conv1D：16 个核，核长 40，步长 1 | **4,000 × 16** | 640 |
| ② | 池化 4 | **1,000 × 16** | 0 |
| ③ | Conv1D：8 个核，核长 40 | **1,000 × 8** | 5,120 |
| ④ | 池化 4 | **250 × 8** | 0 |
| ⑤ | Conv1D：4 个核，核长 40 | **250 × 4** | 1,280 |
| ⑥ | 池化 4 | **62 × 4** | 0 |
| ⑦ | 展平 + FC 128 | **128** | 31,872 |
| ⑧ | FC 5 + softmax | **5** | 645 |
| | **合计** | | **约 39.6k** |

**读法**：长度 4000 → 1000 → 250 → 62（每次 ÷4）；通道 1 → 16 → 8 → 4。
**参数几乎都在第⑦步**（31,872 / 39,557 ≈ 80%）。

**为什么不加更多层**：17（Ma）证明 3 个卷积块 + FC 就能到 98.65%，且参数只有 2 万。

---

## 3. 看我们的 A2（2D CNN）

输入：**64 × 200 的谱图**（64 个 mel 频带 × 200 帧）

| 步骤 | 操作 | 输出形状 | 参数 |
| --- | --- | --- | --- |
| ① | Conv2D：8 通道，3×3 | 64×200×8 | 72 |
| ② | 池化 2×2 | 32×100×8 | 0 |
| ③ | Conv2D：16 通道，3×3 | 32×100×16 | 1,152 |
| ④ | 池化 2×2 | 16×50×16 | 0 |
| ⑤ | Conv2D：32 通道，3×3 | 16×50×32 | 4,608 |
| ⑥ | 池化 2×2 | 8×25×32 | 0 |
| ⑦ | **GAP**（整张图取平均）| 32 | 0 |
| ⑧ | FC 5 + softmax | 5 | 165 |
| | **合计** | | **约 6k** |

**GAP 是什么**：对每张特征图**整体取平均**，把 8×25×32 直接压成 32 个数。
好处：**参数量与输入尺寸无关**——这就是为什么 A2 只有 6k 参数，而如果改用"展平 + FC"，参数会涨到几十万。

## 4. 看 A1 / A2s（浅层模型）

它们不是"网络"，是两个经典分类器：

```
MFCC 39 维 × 200 帧
  → 时间维度取"均值"和"标准差" → 78 维
  → 逻辑回归 / SVM → 5 类
```

| 模型 | 在做什么 | 参数 |
| --- | --- | --- |
| **逻辑回归（LR）** | 给每一维乘一个权重，求和后 softmax | 78×5 + 5 = 395 |
| **SVM（RBF 核）** | 在高维空间找"分界面" | 由支持向量数决定（通常 <2,000）|

**它们的作用**：提供"不用深度网络能做到多少"的参照。

## 6. 三个常见误解

| 误解 | 实际 |
| --- | --- |
| "层越多越好" | 错。17 用 3 个卷积块到 98.65%；24 用 16 层只多 0.28 点 |
| "参数越多越准" | 错。参数与精度无单调关系（见 T3）|

# 附录：输出形状与参数量到底怎么算

## A.1 输出形状的公式

### 卷积（1D / 2D 通用）

```
输出长度 = floor( (输入长度 + 2×补零 − 核长) / 步长 ) + 1
```

| 符号 | 含义 | 我们的取值（A3）|
| --- | --- | --- |
| 输入长度 | 上一层输出 | 4,000 |
| 核长 K | 窗口宽度 | 40 |
| 步长 S | 每次滑多远 | 1 |
| 补零 P | 两端补几个 | 19（same padding）|

**什么是 same padding**：为了让输出长度等于输入长度，两端各补 `(K−1)/2` 个零。
我们的 K=40 是偶数，`(40−1)/2 = 19.5`——实现上会左右补 19 和 20（不对称），**这样输出仍是 4,000**。

> 若不做 same padding（valid），输出会变成 `4000 − 40 + 1 = 3,961`——每层都会缩短，算起来更麻烦。所以我们统一用 same padding。

### 池化

同样公式，但池化没有补零：

```
输出长度 = floor( 输入长度 / 池化核 )     （当 步长 = 池化核 时）
```

例：`floor(4000 / 4) = 1000`，`floor(250 / 4) = 62`（不是 62.5）。

### 2D 的两个方向分别算

A2 的输入是 **64 × 200**（mel 频带 × 帧），高和宽各自用同一个公式；3×3 卷积 + same padding 时两边都不变，2×2 池化时两边都除以 2。

---

## A.2 参数量的公式

### 卷积层

```
参数 = 核长 × 输入通道 × 输出通道   （不加 bias）
```

**为什么不加 bias**：卷积后紧跟 BatchNorm，BN 自带偏移项，bias 会被抵消——所以实现里通常 `bias=False`。

**2D 卷积**：把"核长"换成 `核高 × 核宽`：

```
参数 = 核高 × 核宽 × 输入通道 × 输出通道
```

### BatchNorm

```
参数 = 2 × 通道数    （缩放 γ 与偏移 β）
```

> 部署时 BN 会被"折叠"进卷积，**实际不增加推理参数**。

### 全连接层

```
参数 = 输入维数 × 输出维数 + 输出维数   （+ 输出维数 是 bias）
```

### 全局平均池化（GAP）

```
参数 = 0
```

它只是对每个通道求平均，没有可学习的数。

## A.3 A3 的手算全过程（对着表看）

| 层 | 输入 → 输出 | 形状怎么来 | 参数怎么来 | 参数 |
| --- | --- | --- | --- | --- |
| Conv1 | 4000×1 → **4000×16** | same padding，步长 1 → 长度不变；通道 1→16 | 40 × 1 × 16 | **640** |
| Pool1 | 4000×16 → **1000×16** | 4000 ÷ 4 | 无参数 | 0 |
| Conv2 | 1000×16 → **1000×8** | 长度不变；通道 16→8 | 40 × 16 × 8 | **5,120** |
| Pool2 | 1000×8 → **250×8** | 1000 ÷ 4 | 0 | 0 |
| Conv3 | 250×8 → **250×4** | 长度不变；通道 8→4 | 40 × 8 × 4 | **1,280** |
| Pool3 | 250×4 → **62×4** | floor(250/4)=62 | 0 | 0 |
| Flatten | 62×4 → **248** | 62 个时间点 × 4 通道 | 0 | 0 |
| FC1 | 248 → **128** | — | 248 × 128 + 128 | **31,872** |
| FC2 | 128 → **5** | — | 128 × 5 + 5 | **645** |
| **合计** | | | | **39,557 ≈ 39.6k** |

**验算**：640 + 5,120 + 1,280 + 31,872 + 645 = **39,557** ✓

**两个值得注意的点**

1. **通道在变小（16→8→4），但参数在变大（640→5,120→1,280）**——因为参数量取决于"输入通道 × 输出通道"，第二层的输入通道是 16。
2. **FC1 一个层就占 80%**（31,872 / 39,557）——因为它要连接 248 个输入和 128 个隐藏单元。

## A.4 A2 的手算全过程

| 层 | 输入 → 输出 | 形状怎么来 | 参数怎么来 | 参数 |
| --- | --- | --- | --- | --- |
| Conv1 | 64×200×1 → **64×200×8** | same padding 3×3，两边不变 | 3 × 3 × 1 × 8 | **72** |
| Pool1 | 64×200×8 → **32×100×8** | 两边各 ÷2 | 0 | 0 |
| Conv2 | 32×100×8 → **32×100×16** | 不变 | 3 × 3 × 8 × 16 | **1,152** |
| Pool2 | → **16×50×16** | ÷2 | 0 | 0 |
| Conv3 | 16×50×16 → **16×50×32** | 不变 | 3 × 3 × 16 × 32 | **4,608** |
| Pool3 | → **8×25×32** | ÷2 | 0 | 0 |
| **GAP** | 8×25×32 → **32** | 每通道取平均 | **0** | 0 |
| FC | 32 → **5** | — | 32 × 5 + 5 | **165** |
| **合计** | | | | **5,997 ≈ 6.0k** |

**对比 A3 的 39.6k**：A2 参数只有 A3 的 1/6，因为 **GAP 把 8×25 直接压成 32**，没有大 FC。

## A.5 三个能自己推的小练习

**练习 1**：把 A3 的 Conv1 核长从 40 改成 20，参数量怎么变？
→ `20 × 1 × 16 = 320`（原来 640），少 320。**形状不变**（same padding）。

**练习 2**：把 A3 的 FC1 从 128 改成 64，参数量怎么变？
→ `248 × 64 + 64 = 15,936`（原来 31,872），少约 1.6 万。**总参数降到约 23.7k。**

**练习 3**：把 A2 的 GAP 换成 Flatten + FC 128，会怎样？
→ Flatten 是 `8 × 25 × 32 = 6,400` 维，接 FC 128 → `6,400 × 128 + 128 = 819,328` 个参数——**从 6k 暴涨到 82 万**（约 137 倍）。这正是 GAP 的价值。

---

## A.6 一句话总结

- **形状**由"卷积核/步长/补零"决定：same padding 保持长度，池化按倍率缩短；
- **参数**由"核大小 × 输入通道 × 输出通道"决定（CNN），或"输入维 × 输出维"（FC）；
- **池化与 GAP 不产生参数，但改变后续 FC 的输入维数**——这就是为什么"少用大 FC"能省参数。

# 附录 B：通道数是怎么来的、怎么变

## B.1 一句话

**通道数是设计者定的**（卷积层有几个滤波器就有几个输出通道）；**输入通道数由上一层决定**，不是算出来的。

```
输入通道（上一层给的）  ×  滤波器个数（你定的）  →  输出通道
        1               ×        16              →      16
       16               ×         8              →       8
        8               ×         4              →       4
```

## B.2 一个滤波器看几个通道？

**一个滤波器会同时看**输入的全部通道，输出**一张**特征图。

```
输入：4,000 × 16（16 个通道）
滤波器：一个核长 40 的窗口，但它在 16 个通道上都有一组权重
        → 一次卷积要算 40 × 16 次乘加
输出：4,000 × 1（一个滤波器 → 一个通道）
```

所以用 8 个滤波器，就得到 `4,000 × 8`。

**这也解释了参数量公式**：`核长 × 输入通道 × 输出通道`——乘"输入通道"是因为每个滤波器要覆盖所有输入通道。

## B.3 两种相反的通道安排

| 安排 | 例子 | 特点 |
| --- | --- | --- |
| **边降采样、边加通道** | A2：8 → 16 → 32 | CNN 的教科书做法：空间变小，通道变多，保持"信息总量" |
| **边降采样、边减通道** | A3：16 → 8 → 4 | **17（Ma）的做法**：为了压参数与算力 |

**为什么 A3 要减通道**：1D 波的"模式类型"本来就少（上升沿、下降沿、持续能量），不需要很多通道；而且**通道数直接影响后面 FC 的输入维数**，进而决定参数。

## B.4 通道数对参数量的影响有多大（算给你看）

同样是 A3 的结构，只改通道安排：

| 通道 | Conv1 | Conv2 | Conv3 | 展平维数 | FC1 参数 | **总参数** |
| --- | --- | --- | --- | --- | --- | --- |
| **16 / 8 / 4**（我们的）| 640 | 5,120 | 1,280 | **248** | 31,872 | **39,557** |
| 16 / 32 / 64（教科书式）| 640 | 20,480 | 81,920 | **3,968** | 508,032 | **611,717** |

**通道只放大 4–16 倍，总参数放大约 15 倍**（39.6k → 612k），因为：
**通道数 → 展平维数 → FC 输入 → FC 参数**，是三级放大。

> 612k 已经**超过我们 150k 的预算 4 倍**——所以 A3 必须用"递减通道"。

## B.5 其它会改变通道数的操作

| 操作 | 对通道做什么 | 例子 |
| --- | --- | --- |
| **普通卷积** | 任意改（由滤波器数决定）| 16 → 8 |
| **1×1 卷积（pointwise）** | 任意改，且很便宜（参数 = Cin×Cout）| 常用于"降维" |
| **残差相加（Add）** | **必须相同**，否则加不起来 | ResNet 的 shortcut |
| **拼接（Concat）** | 通道相加 | 20（CardioXNet）的三路拼接：16+8+4 → 28 |
| **GAP** | 把 H×W 压成 1，通道数不变 | 8×25×32 → 32 |
| **深度可分离卷积** | 逐通道卷积不混通道，pointwise 再改通道 | 27 的 GCT |

## B.6 怎么选通道数（三条经验）

1. **先定预算，再排通道**：我们的预算是 ≤150k 参数，A3 在 40k 左右，留了 3 倍余量；
2. **通道不要突然放大**，否则下一层参数暴涨（见 B.4）；
3. **末端用 GAP 而不是大 FC**：GAP 让"通道数"直接等于"FC 输入维数"，不再乘 H×W。

## B.7 一句话总结

> **通道数是你定的超参数；输入通道由上一层决定；通道数通过"展平维数 → FC 输入"被放大成参数量**——所以"减通道"往往比"减层数"更能省参数。

# 附录 C：为什么通道要这么设计（16 → 8 → 4）

## C.1 先说实话：这个安排不是推导出来的

**它来自 17（Ma 2023）的原文**：3 组 Conv+MaxPool、核 20、滤波器 **16/8/4**、池化 4、FC 128、共 20,193 参数。

我们照抄，是因为 **A3 要与 A3-repro（17 的 1:1 复现）可比**——如果 A3 换了通道，那么"A3 vs A3-repro"的差异就无法归因于采样率。

**所以第一层理由是"为了可比"，不是"这样最优"。**

## C.2 17 为什么这么设计（它的三条原则）

17 原文的设计原则是：**不用残差块、用小卷积核、尽早池化以压缩 FC 输入**。

拆开看，这三条都指向同一件事：**控制 FC 的输入维数**。

```
2,000 点 → 池化 4 → 500 → 池化 4 → 125 → 池化 4 → 31
31 个时间点 × 最后通道 4 = 124 维 → FC 128
```

如果最后是 64 通道：`31 × 64 = 1,984 维` → FC 128 = **254,080 参数**（是原来的 8 倍）。

## C.3 三种通道安排的代价（同一结构，只改通道）

| 通道安排 | 展平维数 | FC1 参数 | **总参数** | 超预算（150k）？ |
| --- | --- | --- | --- | --- |
| **16 / 8 / 4**（我们的）| 248 | 31,872 | **39,557** | ✅ |
| 16 / 32 / 64 | 3,968 | 508,032 | **611,717** | ❌ 超 4 倍 |
| 32 / 32 / 32 | 1,984 | 254,080 | **337,925** | ❌ 超 2 倍 |
| 64 / 64 / 64 | 3,968 | 508,032 | **838,917** | ❌ 超 5 倍 |

**换成 GAP 之后**（去掉大 FC）：

| 通道安排 | 展平 | FC1 | 总参数 |
| --- | --- | --- | --- |
| 16 / 8 / 4 + GAP | 4 | 640 | **8,325** |
| 16 / 32 / 64 + GAP | 64 | 8,320 | **112,005** |
| 32 / 32 / 32 + GAP | 32 | 4,224 | **88,069** |

→ **如果改用 GAP，"通道递增"其实也放得下**（112k < 150k）。**限制我们的不是通道，而是那个 FC 128。**

## C.4 那为什么还选递减？

| 理由 | 说明 |
| --- | --- |
| **1. 复现可比** | 与 17 一致（主因）|
| **2. 1D 信号模式少** | 波形里可学的局部模式（起止、能量包络）比图像少得多，不需要很多通道 |
| **3. 递减 = 让信息逐层抽象** | 前层"广撒网"捕捉多种局部模式（16 个），后层把它们组合成少量抽象模式（4 个）|
| **4. 预算冗余** | 39.6k 留了约 4 倍余量给量化与后续改进 |

**代价**：模型容量受限，精度上限可能不如更大的通道安排——这是用"可部署性 + 可比性"换的。

## C.5 2D 那边为什么反过来（递增 8→16→32）？

A2 遵循 CNN 的通用做法：**空间尺寸减半时，通道加倍**，以保持每层的"信息总量"大致不变。

为什么 A3 不这样？因为 A3 后面接的是 **FC 128**，它的输入维数 = 时间点数 × 通道数；通道加倍会让 FC 参数翻倍。而 A2 后面是 **GAP**，**通道数直接等于 FC 输入维数**，与 8×25 无关——所以 A2 可以放心加通道。

**一句话**：**决定通道能不能加的不是"CNN 惯例"，而是"末端用的是 FC 还是 GAP"。**

## C.6 如果以后想改，怎么改（有判据才改）

| 情形 | 动作 |
| --- | --- |
| A3 精度明显低于 A2（>2 点）| 试一次 **16/32/64 + GAP**（估计 112k 参数，仍在预算内），作为**新增臂**，需新 ADR |
| 需要更小模型 | 把 FC 128 换成 GAP（39.6k → 8.3k），但会失去与 17 的可比性 |
| 部署时 RAM 紧张 | 优先 GAP 化，而不是砍通道（砍通道对算力几乎无帮助）|

## C.7 一句话总结

> **通道安排是"预算 + 可比性"共同决定的**：16/8/4 来自 17，为了复现可比；它同时把 FC 压到 248 维，使总参数留在 40k。
> **真正的约束不是通道数，而是末端那个 FC 128**——换成 GAP，通道就有空间加大。
