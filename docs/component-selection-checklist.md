## 2. 探头选型

### 2.1 传感器

- [ ] 确定使用 Piezo、PVDF、MEMS 麦克风还是普通麦克风。
- [ ] 确认 20 到 1000 Hz 范围内的频响和低频截止。
- [ ] 确认灵敏度、噪声底、动态范围和输出阻抗。
- [ ] 确认是否需要电荷放大器或偏置电路。
- [ ] 确认传感器尺寸、贴胸方式和声耦合结构。
- [ ] 确认防震、抗摩擦噪声和抗环境噪声方案。

负责人：队友

依赖：探头外形、贴胸位置和最终传感器方案。

### 2.2 模拟前端

- [ ] 选择低噪声运放或仪表放大器。
- [ ] 实现 20 Hz 高通和 1 kHz 低通。
- [ ] 增加抗混叠滤波，截止频率与 ADC 采样率匹配。
- [ ] 确定增益范围，并保留可调增益或固定增益理由。
- [ ] 确定偏置电压、参考地和单电源/双电源方案。
- [ ] 评估电源噪声、共模干扰和工频干扰。
- [ ] 预留测试点和调试接口。

负责人：队友

### 2.3 ADC

- [ ] 采样率至少支持 8 kHz。
- [ ] 分辨率至少 16-bit，优先选择低噪声 24-bit ADC。
- [ ] 输入形式优先差分，确认单端输入是否足够。
- [ ] 接口选择 I2S 或 SPI，并确认 DMA/DRDY 支持。
- [ ] 确认有效位数、信噪比和输入满量程。
- [ ] 确认与探头 MCU 的供电电平和时钟同步方式。
- [ ] 确认 20 Hz 附近的直流和高通处理不会破坏心音。

负责人：队友

### 2.4 探头 MCU/DSP 与 BLE

- [ ] 确认是否使用 BLE SoC，还是 MCU 加独立 BLE 模块。
- [ ] 支持 ADC 连续采集和 DMA。
- [ ] 支持 4 kHz 或 8 kHz PCM 的实时处理。
- [ ] 支持 20 ms 分帧、序号、时间戳和 CRC。
- [ ] BLE 支持 5.0、GATT 自定义服务和大 MTU。
- [ ] 评估 64 kbps 和 128 kbps 数据量的稳定传输。
- [ ] 确认低功耗休眠、唤醒和连接管理能力。
- [ ] 确认 RAM、Flash、DMA 和调试接口余量。

候选方向：nRF5340、STM32WB、STM32G4 加 BLE 模块等。

负责人：队友主选，双方确认接口。

### 2.5 探头电源和结构

- [ ] 选择小电池、充电触点、稳压和电量检测方案。
- [ ] 选择充电保护、过流保护和低电量指示。
- [ ] 确认电池是否可更换，是否需要运输和认证要求。
- [ ] 确认外壳材料、尺寸、贴胸固定压力和防震结构。
- [ ] 确认 BLE 天线净空或线缆屏蔽、连接器和应力释放。
- [ ] 预留状态 LED、按键和调试接口。

负责人：队友

## 3. 主机选型

### 3.1 主控 MCU/SoC

- [ ] 支持 AI 推理，有足够的 CPU/NPU/DSP 能力。
- [ ] 支持 int8 量化和目标推理框架。
- [ ] RAM 和 Flash 能容纳模型、缓冲区和 UI。
- [ ] 支持 PSRAM 或外部存储，预留模型升级空间。
- [ ] 支持 BLE 和 WiFi，或明确外接无线方案。
- [ ] 支持 LCD、I2S 音频、microSD 和 DMA。
- [ ] 评估目标推理时间和功耗，避免阻塞音频采集。
- [ ] 工具链、开发板和量产资料足够成熟。

候选方向：ESP32-S3、STM32N6、Alif 系列等。

负责人：我主选，队友确认硬件接口。

### 3.2 显示与交互

- [ ] 选择屏幕尺寸、分辨率和接口。
- [ ] 候选规格至少覆盖 240 x 240 SPI 屏幕。
- [ ] 支持波形、BPM、AI 结果和状态显示。
- [ ] 评估刷新率、亮度、阳光下可读性和功耗。
- [ ] 确认双缓冲或 DMA 刷新，避免阻塞推理。
- [ ] 确定按键、旋钮、触控或菜单交互方式。
- [ ] 确认屏幕 FPC、排线和外壳开窗。

负责人：我主选，队友确认结构。

### 3.3 音频输出

- [ ] 选择音频 Codec 或 DAC。
- [ ] 选择 Class-D 功放和小型扬声器。
- [ ] 确认采样率、位深、滤波和音量控制。
- [ ] 确认扬声器尺寸、音腔和功耗。
- [ ] 决定是否需要耳机接口。
- [ ] 确认回放不会干扰 WiFi、BLE 和 AI 推理。

负责人：队友主选，我确认音频数据接口。

### 3.4 无线、存储与电源

- [ ] 确认 BLE 和 WiFi 是否共用一颗芯片。
- [ ] 确认天线形式、净空和辐射认证要求。
- [ ] 选择 microSD 或外部 Flash，并确认容量与速度。
- [ ] 选择电池容量、充电管理、电量计和 USB-C 方案。
- [ ] 确认 WiFi 上传时峰值电流和电源纹波。
- [ ] 确认显示屏、功放、无线和主控的供电域。
- [ ] 预留 OTA、调试串口和固件恢复接口。

负责人：队友主选，双方确认系统资源。

### 3.5 主机结构

- [ ] 确认主机是手持还是随身佩戴。
- [ ] 确认屏幕、控制按键和扬声器布局。
- [ ] 确认电池、PCB、天线和走线的空间。
- [ ] 确认散热、扬声器开孔和麦克风/扬声器隔离。
- [ ] 确认外壳装配、维修和充电可达性。

负责人：队友

## 4. 服务器和存储选型

服务器当前只做数据存储，不做 AI 推理、模型训练和模型管理。

- [ ] 选择部署方式：本地电脑、NAS、实验室服务器或云服务器。
- [ ] 选择数据库：建议先用 SQLite 或 PostgreSQL。
- [ ] 选择对象存储：本地目录、MinIO 或云对象存储。
- [ ] 确认上传接口：HTTPS REST。
- [ ] 确认保存字段：AI 结果、特征、BPM、信号质量、原始心音或波形。
- [ ] 确认单次会话大小和总存储容量。
- [ ] 确认设备认证、访问控制和数据加密。
- [ ] 确认断网缓存、重试和重复上传处理。
- [ ] 确认数据保留期限、导出方式和删除方式。

负责人：我主选，老师确认数据范围。

## 5. 采购或打样前的检查

- [ ] 传感器、ADC、探头 MCU 和 BLE 方案已互相匹配。
- [ ] 主控 SoC、屏幕、音频、WiFi 和外设接口没有冲突。
- [ ] RAM、Flash、PSRAM、DMA 和功耗预算已经核算。
- [ ] 探头和主机之间的供电、通信和机械连接已经确认。
- [ ] 所有器件的封装、工作电压和温度范围满足要求。
- [ ] 关键器件有开发板、参考设计或可购买样品。
- [ ] 关键器件没有停产风险和超长交期。
- [ ] 已准备替代型号，避免单一器件阻塞项目。

## 6. 建议的选型顺序

1. 传感器类型与探头连接方式。
2. ADC 与模拟前端架构。
3. 探头 MCU/BLE 方案。
4. 主机主控与 AI 推理方案。
5. 显示、音频和无线外设。
6. 探头与主机电源方案。
7. 外壳与结构方案。
8. 服务器存储方案和上传字段。

## 7. 当前最先要确认的三件事

- [ ] 探头 BLE SoC/模块的准确型号。
- [ ] 主线 AI 模型对主控算力、RAM 和 Flash 的要求。
- [ ] 服务器需要保存哪些数据，以及是否需要上传原始心音。
