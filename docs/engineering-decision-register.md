## ADR-003：链路 A 采用 BLE 5.0，ESP-NOW 作为备选

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选冻结，待硬件实测 |
| 决策 | 探头到主机采用 BLE 5.0 GATT，优先 2M PHY |
| 候选 | BLE 5、ESP-NOW、Nordic ESB、Wi-Fi |
| 主要优势 | 低功耗、跨厂商、内置安全和配对，理论吞吐高于需求约 10 倍 |
| 主要代价 | 需要验证 BLE 与主机 Wi-Fi 共存、连接间隔和 P95 延迟 |
| 备选条件 | 两端均为 Espressif 且 ESP-NOW 实测吞吐、延迟和共存优于 BLE |
| 验证 | 5 分钟连续传输、丢帧率、P95/最大延迟、重传和 Wi-Fi 共存 |

## ADR-006：主机计算平台架构（待定）

| 项目 | 内容 |
| --- | --- |
| 状态 | 待模型预算确认后选型 |
| 决策问题 | 主机使用单无线 MCU、MCU+NPU+独立无线，还是 Linux SoC |
| 必须满足 | 本地 4 kHz 心音 AI 推理、BLE central、Wi-Fi station/SoftAP、显示、音频回放、本地缓存和电池供电 |
| 候选 A | ESP32-S3：双核 LX7 240 MHz、512 KB 内部 SRAM、外部 PSRAM、2.4 GHz Wi-Fi + BLE 5、向量指令 |
| 候选 B | ESP32-P4 + ESP32-C5/C6：双核 RISC-V 400 MHz、768 KB 内部 SRAM、AI 指令、MIPI-DSI/CSI，P4 本身无无线 |
| 候选 C | STM32N6 + 独立 BLE/Wi-Fi 模块：Cortex-M55 800 MHz、1 GHz NPU 最高 600 GOPS、4.2 MB RAM，需外接无线 |
| 候选 D | Linux SoC/SBC：AI 和 GUI 能力强，但启动、功耗、供电和实时性成本最高 |
| 当前建议 | 原型优先验证 ESP32-S3；若模型或显示超预算，再评估 ESP32-P4+C5；只有 NPU 明确必要时选 STM32N6 |
| 选择门槛 | 先用候选 AI 模型给出 int8 模型大小、峰值 RAM、MACs、目标推理时延和显示/网络并发预算 |
| 验证 | 在开发板上运行真实推理和 BLE/Wi-Fi/显示并发测试，记录峰值 RAM、帧率、延迟和电流 |
| 回退 | 保持 AUD1/LKA1 不变；更换主机 SoC 不改变探头协议 |

| 受影响文件 | `tools/ai/*`、`tests/python/*`、`docs/ai-baseline-plan.md` |

### ADR-007 完整数据 5 折复核（2026-10-08，升级为原型基线）

| 项目 | 内容 |
| --- | --- |
| 新证据 | CirCor 1.0.3 完整公开训练集经官方 SHA256/CRC 校验；874 名有标签受试者、3007 条录音，按患者做 5 折交叉验证 |
| 协议 | 患者级分层分组 5 折；每折从训练池再分约 15% 患者作验证集选阈值；测试折完全不参与训练和调参；窗口 2 s、步长 1 s、每条录音最多 4 窗 |
| 结果 | 患者级 AUROC（5 折均值±标准差）：逻辑回归 all 0.775±0.029、annotated 0.789±0.031；1D CNN all 0.811±0.052、annotated 0.834±0.061。CNN annotated 的 pooled AUROC 0.802（95% CI 0.758–0.841），pooled BA 0.746（0.709–0.783） |
| 判定 | 四组全部超过预先设定的最低门槛（AUROC ≥ 0.70、BA ≥ 0.65）；CNN + annotated 判别能力最好，因此把“小型 1D CNN + 标注窗口”升级为原型基线 |
| 保留的分歧 | CNN annotated 特异度较低（0.810 vs CNN all 0.934）、各折阈值跨度 0.15–0.71，说明工作点和概率标定未稳定，不冻结单一阈值 |
| 仍未冻结 | 主机平台（ADR-006）、目标板量化后的精度/峰值 RAM/P95 时延/电流、以及最终工作点 |
| 证据等级 | E4 本机可复现实验；公开数据为儿科人群，外部隐藏测试集不可得 |
| 下一次复核 | 获得主机候选开发板并完成转换与实测后 |

## ADR-008：毕业设计 MVP 采用 ESP32-S3 + DSP S1/S2 + CNN 杂音筛查（已确认）

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认（毕业设计 MVP 范围）；目标板性能待实测 |
| 日期 | 2026-10-17 |
| 决策问题 | 在“必须边缘部署、先做出来、可演示”的毕业设计约束下，第一版采用哪条技术路线 |
| 决策 | 采用 ESP32-S3 作为第一版主机；S1/S2 先用确定性信号处理和规则检测，杂音筛查继续使用现有小型 1D CNN；所有推理在设备本地完成 |
| 候选 0 | 维持现状：只运行当前杂音二分类 CNN |
| 候选 A | ESP32-S3 + DSP S1/S2 + 当前 CNN 杂音筛查 |
| 候选 B | ESP32-P4 + C6 + 学习型 S1/S2 模型或多任务模型 |
| 候选 C | Raspberry Pi/CM5 类 Linux SoC 本地运行更大模型 |
| 约束 | 不使用手机、服务器或云端推理；允许 PC 训练、导出和离线评估；探头协议 AUD1/LKA1 不变 |
| 术语澄清 | 本次删除的是“MCU + 手机/服务器”外移推理方案；树莓派在设备本地运行模型仍属于边缘候选 C |
| 共享模型数据 | 41,105 参数；INT8 ONNX 68.8 KiB；5,722,944 MAC/窗；0.5 窗/s 对应 2,861,472 MAC/s（E4，本机 PC） |
| S1/S2 数据 | CirCor 本地统计：66,006 个 S1 片段、65,380 个 S2 片段；仅覆盖高质量代表性片段（标签语义 E1；数量 E4；来源 `data/raw/circor/**/*.tsv`，解析规则见 `tools/ai/hs_segments.py`） |
| 当前选择 | 候选 A |
| 主要优势 | 最快形成完整演示链路；复用现有模型和 ESP32-S3 工具链；S1/S2 规则可解释、便于答辩；即使 S1/S2 失败仍可保留杂音筛查 |
| 主要风险 | DSP S1/S2 对噪声和个体差异敏感；目标板 P95/RAM/功耗未实测；S1/S2 不是独立 AI 模型；疾病诊断不在 MVP 范围内 |
| 验证 | S1/S2 事件级 F1、边界误差；杂音患者级 AUROC/BA；ESP32-S3 峰值 RAM、P95、功耗；BLE/Wi-Fi/显示/推理 5 分钟并发 |
| 失败判据 | S1/S2 事件级 F1 < 0.80；杂音患者级 AUROC < 0.70 或 BA < 0.65；峰值 RAM ≥ 可用内存 70%；P95 超过显示周期的 50%；推理期间 BLE 持续丢帧 |
| 回退 | S1/S2 不达标时只保留波形、心率和杂音分数；资源不足时按顺序评估 ESP32-P4+C6、STM32N6、树莓派类边缘主机；不得外移推理 |
| 不在 MVP 内 | 具体疾病诊断、S3/S4、杂音强度/位置/放射方向和多位置融合；这些需要新增标注和独立 ADR |
| 下次复核 | 完成 ESP32-S3 实物链路和首次目标板资源实测后 |

ADR-008 验收条件：

- S1/S2：20 ms 帧级评估，按患者划分；使用 ±100 ms 事件容差报告事件级
  precision、recall、F1，并单独报告 S1/S2 互换率和边界误差。
- 杂音筛查：沿用 2 s 窗、1 s 步长、患者级 5 折协议；报告 AUROC、BA、
  敏感度、特异度。
- 目标板：连续推理 1,000 次，记录平均/P95/最大时延、峰值 heap 和 Flash；
  BLE、Wi-Fi、显示和音频回放并发运行 5 分钟，记录丢帧、断连和复位。
- 边缘约束：断网和关闭外部设备时仍能完成推理与结果显示；不得依赖手机、
  服务器或云端补充推理。

## ADR-014：主机侧音频数据通路用纯 C 整数实现（候选）

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选；PC 上 3 项 ctest 通过、零编译器警告；目标板未测 |
| 日期 | 2026-10-18 |
| 决策问题 | 从 LKA1 无线包到 AI 输入窗口的数据通路放在哪里、用什么实现，才能既在 PC 上自动测试，又能原样移植到 ESP32-S3 |
| 候选 0 | 直接在固件工程里写（与 BLE 回调耦合），只能在板子上验证 |
| 候选 A | 纯 C、无动态分配、整数运算的独立库 + 调用方拥有的环形缓冲 |
| 候选 B | float32 + malloc，移植时再改 |
| 候选 C | C++ 容器（std::vector/deque） |
| 当前选择 | 候选 A |
| 量化数据 | 63 阶 Q15 Blackman-sinc（截止 1700 Hz，取自 Node 参考实现）；实测 440 Hz 增益 1.0003（+0.002 dB）、1900 Hz 增益 0.0436（−27.2 dB）；约 0.5 MMAC/s、约 1 MB/s；默认 32 帧环形缓冲 = 5120 B，2 s AI 窗口需 100 帧 = 16000 B（E4 本机实测 + 计算） |
| 主要优势 | 与硬件解耦，逻辑全部能用 ctest 在 PC 上测；零动态分配、零运行时浮点（`nm` 只剩 memcpy/memmove/memset 与既有协议符号）；复用既有 `link_a_reassembler` 与 `audio_protocol_decode_frame`，不复制协议逻辑 |
| 主要代价 | 调用方必须自己提供缓冲并保证容量；Q15 与 Node 的 float64 输出不是逐位一致（≤1 LSB） |
| 关键设计（详见头文件 D1~D7） | D1 Q15 vs float：选 Q15，跨工具链确定性优先于与模拟器逐位一致；D2 复用 Node 的 63 阶滤波设计，半带 31 阶会让 1900 Hz 无法可靠抑制；D3 调用方拥有的平坦缓冲；D4 记住最近 4 个被取代的 session_id 并丢弃其迟到包，防止旧包把重组器拉回旧会话；D5 复用完整 AUD1 解码；D6 窗口读取全有或全无，避免把缩短的窗口喂给模型；D7 默认 32 帧 |
| 已修正的错误 | 本轮任务说明把"32 帧 = 2.56 s"写错了：32×80=2560 采样，@4 kHz 是 **0.64 s**。2 s 窗口要 100 帧，调用方必须显式用 `HOST_PIPELINE_AI_WINDOW_FRAMES` 初始化。已在头文件 D7 记录，默认值按原要求保持 32 |
| 主要风险 | ① 非线程安全，BLE 回调与 AI/显示线程之间必须由调用方加锁；② session_id 在 4 次会话内被复用时会被误判为过期，只能靠 `host_pipeline_reset()` 恢复；③ 既有重组器未处理"已交付旧帧在新序号开始后被完整重传"的情况，修复需改冻结的 `link_a_protocol.c` |
| 验证 | `ctest` 8 组用例：乱序、重复、CRC 损坏、缺片、会话隔离、环形回绕与溢出计数、抽取器通阻带与分块一致性、确定性；另用 ASan+UBSan 构建复核 |
| 失败判据 | 任一 ctest 失败；抽取器 440 Hz 增益 < 0.9 或 1900 Hz 增益 > 0.1；同一输入两次运行输出不一致；目标板上出现动态分配或浮点依赖 |
| 回退 | 抽取器改 float32（保持系数与测试阈值不变）；容量不足时增大环形缓冲；线程问题改为单线程事件循环 |
| 受影响文件 | `shared/include/host_pipeline.h`、`shared/src/host_pipeline.c`、`tests/test_host_pipeline.c`、`CMakeLists.txt` |
| 下次复核 | 接入 ESP-IDF 固件骨架并在 ESP32-S3 上测 RAM/时延后 |

### ADR-010 实现偏离说明（2026-10-18）

| 项目 | 内容 |
| --- | --- |
| 原记录 | 主机只保存 1 个 peer 绑定信息 |
| 实现偏离 | `CONFIG_BT_NIMBLE_MAX_BONDS=3` |
| 原因 | 设为 1 时 GCC 14 对上游 `ble_store_nvs.c:820` 报 `-Werror=array-bounds` 假阳性，而 IDF 不应被修改 |
| 实际行为 | 仍然只维持 1 条连接、按 UUID 过滤扫描；"单探头"由行为约束而非 NVS 槽位数保证 |
| 影响 | 无协议影响；存储多占少量 NVS。若将来要求严格单绑定，需上游修复或允许关闭该 `-Werror` |
| 状态 | 记录在案，不改 ADR-010 的候选结论 |

### ADR-011 低频/幅度证据的否定结果（2026-10-18）

| 项目 | 内容 |
| --- | --- |
| 假设 | 高心率下收缩期与舒张期接近，动态规划无法判相位；S1 通常比 S2 更低沉（过零率更低），可作先验打破歧义 |
| 方法 | 把过零率与包络幅度的稳健 z 分数作为动态规划的单步代价，并按冻结划分做参数选择：前 3 折（200 条）挑选权重，后 2 折（400 条 / 244 人）只用一次作验证 |
| 结果（调参集） | 权重 0/0：macro F1 **0.767**、互换 0.150；zcr 0.5：0.559 / 0.391；zcr 1.5：0.556 / 0.396；幅度 0.3：0.580 / 0.358 |
| 结果（留出集） | 选中权重为 0/0，留出集 macro F1 **0.803**（95% CI 0.769–0.838）、互换 0.106 |
| 判定 | **假设被推翻**。低频/幅度证据在真实 CirCor 录音上不可靠：加入后 F1 下降约 0.21，互换率上升约 0.24。默认权重保持 0，代码保留为可复现消融 |
| 可能的解释 | ①过零率在 ±30 ms 窗内受噪声与杂音影响大；②S1 更低沉在部分听诊位置不成立（主动脉区 S2 可更响）；③单步代价权重 0.5 已足以压过间隔模型（间隔代价量级约 0.01–1） |
| 影响 | 高心率（>120 bpm）子组仍是主要失败源（macro 0.604、互换 0.265），未解决 |
| 可复现 | `python tools/ai/tune_s1s2_labeler.py --dataset data/processed/circor`；结果 `data/reports/s1s2-labeler-tuning.json` |
| 未尝试 | 用"心率→收缩期/舒张期比例"的生理先验替代频谱先验；该方向更贴合失败机理，但需要单独实验与 ADR |
| 对验收的含义 | 全队列患者级 macro F1 0.772（95% CI 0.756–0.789），**仍低于 0.80**；不能因为留出集 0.803 就宣布通过，那是子集 |
