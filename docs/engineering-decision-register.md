## ADR-001：产品采用二体式无线探头 + 独立主机

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 |
| 决策 | 探头负责采集和 BLE 发送，主机负责显示、回放、AI 和外部通信 |
| 候选 | 一体式、二体式有线、二体式无线 |
| 主要优势 | 探头可小型化；主机有足够资源运行 AI 和 UI；适合连续测量 |
| 主要代价 | 需要两块电源、两个无线端和更复杂的联调 |
| 验证 | 探头续航、佩戴稳定性、BLE 连续传输和主机离线工作 |

## ADR-002：20~1000 Hz 带宽、8 kHz 采集、4 kHz AI 输入

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选确认，待真实信号验证 |
| 决策 | 8 kHz 单声道 16-bit 采集，带限抽取到 4 kHz |
| 候选 | 4 kHz 直接采集、8 kHz、16 kHz、44.1/48 kHz |
| 主要优势 | 8 kHz 为 1 kHz 心音留出抗混叠余量，同时降低计算和存储 |
| 主要代价 | 需要可靠的模拟抗混叠和 2:1 数字抽取 |
| 验证 | 20/100/440/1000 Hz 正弦注入、真实心音频谱和模型输入一致性 |

## ADR-003：链路 A 采用 BLE 5.0，ESP-NOW 作为备选

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选冻结，待硬件实测 |
| 决策 | 探头到主机采用 BLE 5.0 GATT，优先 2M PHY |
| 候选 | BLE 5、ESP-NOW、Nordic ESB、Wi-Fi |
| 主要优势 | 低功耗、跨厂商、内置安全和配对，理论吞吐高于需求约 10 倍 |
| 主要代价 | 需要验证 BLE 与主机 Wi-Fi 共存、连接间隔和 P95 延迟 |
| 备选条件 | 两端均为 Espressif 且 ESP-NOW 实测吞吐、延迟和共存优于 BLE |
| 验证 | 5 分钟连续传输、丢帧率、P95/最大延迟、重传和 Wi-Fi 共存 |

## ADR-004：链路 B 采用 Wi-Fi 连接手机或服务器

| 项目 | 内容 |
| --- | --- |
| 状态 | 已确认 2026-10-07 |
| 决策 | 主机通过 Wi-Fi 连接手机、外部 AP、本地服务器或手机热点 |
| 候选 | BLE GATT、经典蓝牙 SPP、Wi-Fi SoftAP/Station |
| 主要优势 | 吞吐充足，跨 Android/iOS 不依赖 SPP，支持直接访问服务器 |
| 主要代价 | 主机功耗和射频共存测试增加，SoftAP 与云端上传存在网络切换问题 |
| 验证 | SoftAP、外部 AP、手机热点三种模式，以及 BLE/Wi-Fi 同时工作测试 |

## ADR-005：应用层使用 AUD1，无线链路使用 LKA1

| 项目 | 内容 |
| --- | --- |
| 状态 | 已实现并通过黄金向量测试 |
| 决策 | 352 B AUD1 帧；LKA1 负责分片、重组、CRC 和重复包抑制 |
| 候选 | 直接发送结构体、纯字节流、固定应用帧 + 分包层 |
| 主要优势 | 协议与无线制式解耦，便于替换 BLE、ESP-NOW 或 ESB |
| 主要代价 | 增加 22 B 链路开销和重组逻辑 |
| 验证 | C/Node 黄金包、CRC 损坏、乱序、丢片、重复包和 5 分钟连续运行 |

## ADR-006：主机计算平台架构（待定）

| 项目 | 内容 |
| --- | --- |
| 状态 | 待模型预算确认后选型 |
| 决策问题 | 主机使用单无线 MCU、MCU+NPU+独立无线，还是 Linux SoC |
| 必须满足 | 本地 4 kHz 心音 AI 推理、BLE central、Wi-Fi station/SoftAP、显示、音频回放、本地缓存和电池供电 |
| 候选 A | ESP32-S3：双核 LX7 240 MHz、512 KB 内部 SRAM、外部 PSRAM、2.4 GHz Wi-Fi + BLE 5、向量指令 |
| 候选 B | ESP32-P4 + ESP32-C5/C6：双核 RISC-V 400 MHz、768 KB 内部 SRAM、AI 指令、MIPI-DSI/CSI，P4 本身无无线 |
| 候选 C | STM32N6 + 独立 BLE/Wi-Fi 模块：Cortex-M55 800 MHz、1 GHz NPU 最高 600 GOPS、4.2 MB RAM，需外接无线 |
| 候选 D | Linux SoC/SBC：AI 和 GUI 能力强，但启动、功耗、供电和实时性成本最高 |
| 当前建议 | 原型优先验证 ESP32-S3；若模型或显示超预算，再评估 ESP32-P4+C5；只有 NPU 明确必要时选 STM32N6 |
| 选择门槛 | 先用候选 AI 模型给出 int8 模型大小、峰值 RAM、MACs、目标推理时延和显示/网络并发预算 |
| 验证 | 在开发板上运行真实推理和 BLE/Wi-Fi/显示并发测试，记录峰值 RAM、帧率、延迟和电流 |
| 回退 | 保持 AUD1/LKA1 不变；更换主机 SoC 不改变探头协议 |

## ADR-007：第一版端侧心音 AI 基线与工具链（候选）

| 项目 | 内容 |
| --- | --- |
| 状态 | 原型基线（2026-10-08 完整数据复核）；目标板实测前不视为最终冻结，历史见下方两个补充小节 |
| 日期 | 2026-10-07 |
| 决策问题 | 第一版主机端异常筛查采用哪种数据集、模型结构和量化工具链 |
| 约束 | 4 kHz 单声道、2 s 窗、患者级划分、本地推理、BLE/Wi-Fi/显示并发、电池供电 |
| 候选 A | 维持现状：主机不推理，AI 放到手机或服务器 |
| 候选 B | 40 带 log-mel 统计特征 + 逻辑回归（NumPy，零框架依赖） |
| 候选 C | 小型 1D CNN（4 个卷积块，约 4.1 万参数），PyTorch 训练，导出 ONNX，静态 INT8 量化 |
| 候选 D | ResNet/TCN/轻量 Transformer，容量更大但资源与进度风险更高 |
| 当前选择 | 候选 C 作为第一版主候选，候选 B 作为低成本对照；候选 D 暂不进入 |
| 量化数据 | 41,105 参数；FP32 权重 162.0 KiB；INT8 ONNX 68.8 KiB；单窗 5,722,944 MACs；PC PyTorch 均值 0.75 ms / P95 0.87 ms；PC ONNX INT8 均值 0.119 ms（均为 E4 本机实测，不代表目标板） |
| 数据现状 | CirCor 1.0.3 官方页面：5272 条录音、1568 名受试者、4 kHz、ODC-By 1.0（E1）。当前仅下载 24 名受试者、79 条录音的受限子集，指标不可用于模型质量结论 |
| 主要优势 | 模型和 MACs 远小于候选主机预算；训练、量化、导出和预算统计可一键复现；不改变探头侧协议 |
| 主要代价 | ONNX INT8 不是目标板最终运行格式；仍需转换为 ESP-DL/TFLite Micro/CubeAI 并在开发板复测 |
| 主要风险 | 弱标签和类别不平衡；受限网络导致完整数据集未到位；PC 延迟不能外推到 MCU；与 BLE/Wi-Fi/显示并发可能抢占 CPU |
| 验证 | 完整 CirCor 患者级测试集 AUROC/敏感度/特异度；INT8 相对 FP32 指标变化；目标板峰值 RAM、P95 时延、电流和 5 分钟 BLE 丢帧测试 |
| 失败判据 | 患者级 AUROC < 0.70 或 balanced accuracy < 0.65；INT8 AUROC 下降 > 0.03；目标板 P95 超过显示周期 50%；峰值 RAM 超过可用内存 70%；推理期间 BLE 持续丢帧 |
| 回退 | 先改窗口/特征/训练策略，再评估候选 D；资源超预算时按 ADR-006 回退到 ESP32-P4+C5 或 STM32N6；AUD1/LKA1 协议不变 |
| 受影响文件 | `tools/ai/*`、`tests/python/*`、`docs/ai-baseline-plan.md` |
| 下次复核 | 完整 CirCor 数据处理完成，或获得第一块主机候选开发板时 |

### ADR-007 补充证据（2026-10-08，状态仍为候选）

| 项目 | 内容 |
| --- | --- |
| 新证据 | 用 CirCor `.tsv` 分割标注筛选高质量窗口后，子集测试集窗口级 AUROC：逻辑回归 0.568→0.729，1D CNN 0.569→0.675；患者级 AUROC 两者均 0.750→1.000 |

### ADR-007 完整数据 5 折复核（2026-10-08，升级为原型基线）

| 项目 | 内容 |
| --- | --- |
| 新证据 | CirCor 1.0.3 完整公开训练集经官方 SHA256/CRC 校验；874 名有标签受试者、3007 条录音，按患者做 5 折交叉验证 |
| 协议 | 患者级分层分组 5 折；每折从训练池再分约 15% 患者作验证集选阈值；测试折完全不参与训练和调参；窗口 2 s、步长 1 s、每条录音最多 4 窗 |
| 结果 | 患者级 AUROC（5 折均值±标准差）：逻辑回归 all 0.775±0.029、annotated 0.789±0.031；1D CNN all 0.811±0.052、annotated 0.834±0.061。CNN annotated 的 pooled AUROC 0.802（95% CI 0.758–0.841），pooled BA 0.746（0.709–0.783） |
| 判定 | 四组全部超过预先设定的最低门槛（AUROC ≥ 0.70、BA ≥ 0.65）；CNN + annotated 判别能力最好，因此把“小型 1D CNN + 标注窗口”升级为原型基线 |
| 保留的分歧 | CNN annotated 特异度较低（0.810 vs CNN all 0.934）、各折阈值跨度 0.15–0.71，说明工作点和概率标定未稳定，不冻结单一阈值 |
| 仍未冻结 | 主机平台（ADR-006）、目标板量化后的精度/峰值 RAM/P95 时延/电流、以及最终工作点 |
| 证据等级 | E4 本机可复现实验；公开数据为儿科人群，外部隐藏测试集不可得 |
| 下一次复核 | 获得主机候选开发板并完成转换与实测后 |
