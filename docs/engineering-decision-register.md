## ADR-003：链路 A 采用 BLE 5.0，ESP-NOW 作为备选

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选冻结，待硬件实测 |

## ADR-006：主机计算平台架构（待定）

| 项目 | 内容 |
| --- | --- |
| 状态 | 待模型预算确认后选型 |
| 决策问题 | 主机使用单无线 MCU、MCU+NPU+独立无线，还是 Linux SoC |
| 必须满足 | 本地 4 kHz 心音 AI 推理、BLE central、Wi-Fi station/SoftAP、显示、音频回放、本地缓存和电池供电 |
| 候选 A | ESP32-S3：双核 LX7 240 MHz、512 KB 内部 SRAM、外部 PSRAM、2.4 GHz Wi-Fi + BLE 5、向量指令 |
| 候选 B | ESP32-P4 + ESP32-C5/C6：双核 RISC-V 400 MHz、768 KB 内部 SRAM、AI 指令、MIPI-DSI/CSI，P4 本身无无线 |
| 候选 C | STM32N6 + 独立 BLE/Wi-Fi 模块：Cortex-M55 800 MHz、1 GHz NPU 最高 600 GOPS、4.2 MB RAM，需外接无线 |
| 候选 D | Linux SoC/SBC：AI 和 GUI 能力强，但启动、功耗、供电和实时性成本最高 |
| 当前建议 | 原型优先验证 ESP32-S3；若模型或显示超预算，再评估 ESP32-P4+C5；只有 NPU 明确必要时选 STM32N6 |
| 选择门槛 | 先用候选 AI 模型给出 int8 模型大小、峰值 RAM、MACs、目标推理时延和显示/网络并发预算 |
| 验证 | 在开发板上运行真实推理和 BLE/Wi-Fi/显示并发测试，记录峰值 RAM、帧率、延迟和电流 |
| 回退 | 保持 AUD1/LKA1 不变；更换主机 SoC 不改变探头协议 |

### ADR-006 资源预算输入（2026-10-18）

| 项目 | 内容 |
| --- | --- |
| 目的 | 把主机平台选型从"感觉够用"变成"算得出来"，但不改变 ADR-006 的待定状态 |
| 实测基线 | ESP32-S3 固件（含心率）：DIRAM 169,979/341,760（49.74%），余量 **171,781 B**；`.bss` 82,208（环形 25,600 + AI 窗口 16,000 + 心率 35,448 + 其他 5,160）；Flash 镜像 512,399；IRAM 100% |
| 新增需求（估算） | INT8 权重 70,451（ADR-007 实测尺寸）+ 激活 ~32,768 + LVGL 30,720 + NimBLE 25,600 + Wi-Fi 61,440 + 栈 20,480 |
| 关键结论 1 | 若权重驻留 RAM，共需 241,459 B，**差 69,678 B，放不下** |
| 关键结论 2 | 若权重驻留 flash（`const`/memory-mapped），需 171,008 B，余量只剩 **+773 B**，等于零余量 |
| 关键结论 3 | 显示从 320×240 升到 800×480，帧缓冲 153,600 → 768,000 B、带宽 4.6 → 23.0 MB/s，PSRAM 压力显著上升 |
| 判定规则 | ≤320×240 SPI 屏 + 权重入 flash → S3 仍可但需实测堆余量；RGB 并口屏（≥480×320）或双帧缓冲 → 评估 P4+C6；模型 >100 KB 或激活 >64 KB → 评估 P4+C6 或更大 RAM |
| 证据等级 | 基线为 E2/E4 实测；新增需求中激活、LVGL、协议栈、功耗均为 E4 估算，必须在目标板复测 |
| 验证 | 上板后复测 DIRAM 余量、运行期最小空闲堆、ESP-DL 真实激活内存、PSRAM 带宽争用、显示刷新下的 P95 推理时延、三种功耗组合 |
| 详细记录 | `docs/host-resource-budget.md` |
| 下次复核 | 显示方案确定或首块开发板到位后 |

### ADR-007 完整数据 5 折复核（2026-10-08，升级为原型基线）

| --- | --- |
| 新证据 | CirCor 1.0.3 完整公开训练集经官方 SHA256/CRC 校验；874 名有标签受试者、3007 条录音，按患者做 5 折交叉验证 |

## ADR-014：主机侧音频数据通路用纯 C 整数实现（候选）

| 项目 | 内容 |
| --- | --- |
| 状态 | 候选；PC 上 3 项 ctest 通过、零编译器警告；目标板未测 |
| 日期 | 2026-10-18 |
| 决策问题 | 从 LKA1 无线包到 AI 输入窗口的数据通路放在哪里、用什么实现，才能既在 PC 上自动测试，又能原样移植到 ESP32-S3 |
| 候选 0 | 直接在固件工程里写（与 BLE 回调耦合），只能在板子上验证 |
| 候选 A | 纯 C、无动态分配、整数运算的独立库 + 调用方拥有的环形缓冲 |
| 候选 B | float32 + malloc，移植时再改 |
| 候选 C | C++ 容器（std::vector/deque） |
| 当前选择 | 候选 A |
| 量化数据 | 63 阶 Q15 Blackman-sinc（截止 1700 Hz，取自 Node 参考实现）；实测 440 Hz 增益 1.0003（+0.002 dB）、1900 Hz 增益 0.0436（−27.2 dB）；约 0.5 MMAC/s、约 1 MB/s；默认 32 帧环形缓冲 = 5120 B，2 s AI 窗口需 100 帧 = 16000 B（E4 本机实测 + 计算） |
| 主要优势 | 与硬件解耦，逻辑全部能用 ctest 在 PC 上测；零动态分配、零运行时浮点（`nm` 只剩 memcpy/memmove/memset 与既有协议符号）；复用既有 `link_a_reassembler` 与 `audio_protocol_decode_frame`，不复制协议逻辑 |
| 主要代价 | 调用方必须自己提供缓冲并保证容量；Q15 与 Node 的 float64 输出不是逐位一致（≤1 LSB） |
| 关键设计（详见头文件 D1~D7） | D1 Q15 vs float：选 Q15，跨工具链确定性优先于与模拟器逐位一致；D2 复用 Node 的 63 阶滤波设计，半带 31 阶会让 1900 Hz 无法可靠抑制；D3 调用方拥有的平坦缓冲；D4 记住最近 4 个被取代的 session_id 并丢弃其迟到包，防止旧包把重组器拉回旧会话；D5 复用完整 AUD1 解码；D6 窗口读取全有或全无，避免把缩短的窗口喂给模型；D7 默认 32 帧 |
| 已修正的错误 | 本轮任务说明把"32 帧 = 2.56 s"写错了：32×80=2560 采样，@4 kHz 是 **0.64 s**。2 s 窗口要 100 帧，调用方必须显式用 `HOST_PIPELINE_AI_WINDOW_FRAMES` 初始化。已在头文件 D7 记录，默认值按原要求保持 32 |
| 主要风险 | ① 非线程安全，BLE 回调与 AI/显示线程之间必须由调用方加锁；② session_id 在 4 次会话内被复用时会被误判为过期，只能靠 `host_pipeline_reset()` 恢复；③ 既有重组器未处理"已交付旧帧在新序号开始后被完整重传"的情况，修复需改冻结的 `link_a_protocol.c` |
| 验证 | `ctest` 8 组用例：乱序、重复、CRC 损坏、缺片、会话隔离、环形回绕与溢出计数、抽取器通阻带与分块一致性、确定性；另用 ASan+UBSan 构建复核 |
| 失败判据 | 任一 ctest 失败；抽取器 440 Hz 增益 < 0.9 或 1900 Hz 增益 > 0.1；同一输入两次运行输出不一致；目标板上出现动态分配或浮点依赖 |
| 回退 | 抽取器改 float32（保持系数与测试阈值不变）；容量不足时增大环形缓冲；线程问题改为单线程事件循环 |
| 受影响文件 | `shared/include/host_pipeline.h`、`shared/src/host_pipeline.c`、`tests/test_host_pipeline.c`、`CMakeLists.txt` |
| 下次复核 | 接入 ESP-IDF 固件骨架并在 ESP32-S3 上测 RAM/时延后 |

### ADR-011 参数方法学债结案（2026-10-18，嵌套患者级选参）

| 项目 | 内容 |
| --- | --- |
| 待验证问题 | `same_state_penalty`、`min_gap_separation`、`merge_fraction`、`merge_min_gap_s` 是在全队列的一个抽样上调出来的，而同一队列又被用来报告 0.772，因此该数字可能偏乐观 |

| 网格 | `same_state_penalty` ∈ {0.5, 1.5, 3.0}；`min_gap_separation` ∈ {1.02, 1.05, 1.10}；`merge_fraction` ∈ {0, 0.55}；`merge_min_gap_s` ∈ {0.10, 0.15}（合并关闭时不交叉该项），共 27 组 |

| 与原报告的差异 | 原 0.772 与嵌套默认 0.784 的差别来自聚合口径（全队列池化的患者级宏平均 vs 逐折宏平均再平均）与折构成，**不是调参乐观偏差**。原数字没有虚高 |
| 参数稳定性 | 5 折全部选择 `same_state_penalty=0.5`、开启近峰合并、`merge_min_gap_s=0.15`；`min_gap_separation` 在 1.02–1.10 间波动，说明该维几乎平坦、曲面不敏感 |
| 选参收益 | +0.008（0.792 vs 0.784），远小于折间标准差 0.017，属于噪声量级 |

| 证据等级 | E4（本机可复现）；复现命令见 `docs/handoff-2026-10-18.md` 第 8 节与 `tools/ai/nested_tune_s1s2.py` |

| 下一步 | 已按 ADR-008 的顺序转向"高心率子组的生理先验"；若仍 < 0.80 则回退为只输出波形、心率、杂音分数 |

### ADR-011 高心率生理先验（2026-10-18，负结果 + 净改进）

| 项目 | 内容 |
| --- | --- |
| 目标 | 用"心率 → 收缩期/舒张期时长"的生理关系替代已失效的间隔聚类，把 >120 bpm 的互换率从 0.265 压到 0.20 以下 |
| 候选 C | 纯间隔聚类（旧行为） |
| 候选 A | `S = a·√RR + b`，`D = RR − S`；三种用法：全部启用 / 门控 HR>120 / 仅用于判定"哪一簇是 S1"（`orient`，保留本录音的簇时长） |
| 候选 B | 固定式 `S = clamp(0.32·√RR, 0.18, 0.34)`，门控 HR>120 |
| 已排除 | 频谱/幅值证据（此前已证伪，F1 0.767→0.556）；blend 0.25/0.5/0.75；parity 中位数作幅值；MAD/呼吸变异定向；EM 细化（无法打破相位对称） |
| 当前选择 | 候选 A 的 `orient` 用法，门控 HR>120，默认 `gap_prior="orient"` |
| 拟合协议 | 峰值检测与先验无关；把检出峰按 ±100 ms 匹配参考事件，按录音取 S1→S2 与 S2→S1 间隔中位数，`RR` 为两者之和，跨录音对 `√RR` 做 OLS。嵌套 5 折：外层留出 1 折，其余 4 折拟合。冻结默认常数为**只用折 0–3** 拟合：`a=0.3567068`、`b=−0.0184100`（逐折 a∈[0.3508,0.3662]，b∈[−0.0254,−0.0138]）；折 4 完全未参与 |
| 嵌套结果（5 折留出均值±std） | 旧行为 0.7836±0.0199、互换 0.1102；**选定方案 0.7975±0.0210、互换 0.1101**；>120 组 0.6010→**0.6645**，互换 0.2768→**0.2733**；≤120 组不变（0.8068/0.0815） |
| 单次全队列（冻结常数） | 总体 macro **0.7839**（旧代码 0.7708）、互换 0.1116；>120 组 macro **0.6577**（旧 0.5992）、互换 **0.2706**（旧 0.2755，目标 0.20）；边界 p95 0.0418 s 不变 |
| 判据 | 总体 F1 不低于 0.772 → 通过；≤120 不退化 → 通过；**>120 互换 < 0.20 → 不通过**（0.2706） |
| 关键诊断 | 瓶颈是**S1/S2 的定向**而不是时长：把簇时长固定、只换成"神谕定向"，>120 互换可到 **0.098**、macro 0.828；而"神谕时长 + 旧定向"仍是 0.272。人群回归只能为约 70% 的高心率录音给出正确定向，**139/516 条 >120 bpm 录音整段反相**，占该组匹配数的 20.6%；其余约 30% 的患者收缩期确实比人群回归预测更长，单靠时间无法判定 |
| 结论 | 这是一个**清晰的负结果**：仅靠心率先验无法达到 0.20 的互换率目标。同时它带来净改进（总体 +0.013、>120 组 +0.059），且 ≤120 bpm 行为逐事件不变（`gap_prior="cluster"` 在 80/80 抽样录音上与旧代码完全一致） |
| 产品影响 | **ADR-008 的 S1/S2 验收仍未通过**（嵌套 0.7975 < 0.80）。更重要的是"平均值掩盖灾难"：高心率组存在整段反相，用户会看到 S1/S2 互换。因此 MVP **不应把 S1/S2 作为权威标注展示**，按 ADR-008 回退为波形/心率/杂音分数，S1/S2 最多作为低置信度提示 |
| 回退 | `DetectorConfig(gap_prior="cluster")` 一行恢复旧默认 |
| 下一步候选 | 逐录音定向线索（如舒张期的呼吸变异），或接受定向上限；不作为当前优先级 |

### ADR-009 是否需要更换主数据集（2026-10-18，结论：不更换）

| 项目 | 内容 |
| --- | --- |
| 触发问题 | S1/S2 事件级（嵌套 0.7975）与心率（13.5% 粗错）未达预期，怀疑 CirCor 本身不适合作为主数据集 |
| 证据 1：主任务成立 | 杂音筛查在 CirCor 上患者级 AUROC **0.848 ± 0.051**（CNN annotated）、0.789（log-mel）、0.801（MFCC+Δ），874 人/3007 条，患者级 5 折、冻结划分。若数据集本身不可用，主任务不可能达到该水平（E4） |
| 证据 2：标注自洽 | 以参考标注计算每录音的 S1→S2（收缩期）与 S2→S1（舒张期）中位数：参考心率 ≤120 bpm 的 2471 条中，**仅 1.0%** 出现"收缩期 > 舒张期"；>120 bpm 的 691 条中为 **17.5%**；全体比值中位 0.77。标注与生理一致，**不是标注噪声**（E4） |
| 证据 3：高心率不可分是物理限制 | >120 bpm 组收缩期中位 215 ms、舒张期中位 240 ms，二者接近；17.5% 的录音收缩期本来就长于舒张期。任何"短间隔=收缩期"的时间规则在这些录音上必然反相，与数据集无关 |
| 证据 4：替代数据集无一项更优 | ZCHSound：无 S1/S2 标注、数据许可未确认；PASCAL A/B：176/656 条、许可不明、无可靠患者 ID，仅 461 条有标签；PhysioNet 2016：**缺逐条患者 ID**，无法做患者级划分；HLS-CMDS：模拟人、非真实患者。详见 `docs/pcg-dataset-audit-2026-10-17.md` |
| 证据 5：CirCor 的真实局限（已记录，不构成更换理由） | 儿科单一中心、874 名有标签患者、S1/S2 标注只覆盖录音约 52%（其余为 `label 0`，已用 ADR-015 掩码口径处理）、无逐条设备字段、4 kHz 采样 |
| 判定 | **不更换主数据集。** 无法算好的不是数据集，而是"仅凭时间信息判定 S1/S2 身份"这一方法在高心率下的固有上限 |
| 若未来要换，触发条件 | ① 需要成人泛化：引入成人数据集（如 HSBP-DB 仅作外部压力测试）；② 需要解决定向：引入同步 ECG（R 峰直接给收缩期起点）或双部位录音，属产品形态变更；③ 需要更强外部验证：ZCHSound 许可书面确认后作为外部测试集 |
| 不因以下理由更换 | 指标不理想本身不构成更换理由；更换会破坏与 ADR-007 历史数字的可比性（冻结划分 `1f212dea…`） |
| 下一步 | 维持 CirCor；若要加强泛化结论，加外部验证集而不是换主集 |

### ADR-014 心率检测器移植（2026-10-18，C 版）

| 项目 | 内容 |
| --- | --- |
| 决策问题 | 心率要进 MVP，需要一个能在 ESP32-S3 上跑、且与 Python 基线可比的事件检测实现 |
| 关键简化 | 心率只需要稳定的事件时刻，**不需要 S1/S2 标签**；C 版因此完全省掉两状态动态规划与频谱/幅值证据 |
| 候选 A | float32 + 每窗中位数作为噪声底（**当前选择**） |
| 候选 B | 3 s 混合底（agreement 78.8%，与 A 同量级） |
| 候选 C | 运行分位数 / p99 用运行最大值（75.0%，更差，已否决） |
| 候选 D | 完全复刻 4 s 块中位数与整段 p99（agreement 会更高，但需更长缓冲；未实现） |
| 资源实测 | `sizeof(hr_detector_t)=360 B` + 调用方工作缓冲 **35,096 B**（8774 floats）；`.data/.bss = 0`；用 `-fstack-usage` 测得 `push_hop` 栈 1760 B；PC 上 **1.48–1.52 ms / 2 s 窗**；无 `IRAM_ATTR`，代码与系数表进 flash（IRAM 已 100%，未被占用） |
| 端口保真度 | 117,577 个匹配事件：C 找到 Python 事件的 **97.60%**，C 的 **96.38%** 是 Python 事件；\|Δt\| 中位 **0.05 ms**、p90 0.25 ms、93.3% ≤1 ms。129 阶带通系数与 Python 设计差 **1.8e-9** |
| 一致性判据 | 原定"≥95% 在 ±2 bpm 内与 Python 一致" → **未通过（79.2%）** |
| 准确性判据 | "C 对参考心率 MAE ≤ Python+1" → **通过：6.14 vs Python 6.76**（p95 39.5 vs 44.1），即 C 版在同批数据上反而更接近标注真值 |
| 未达标原因（实测） | DSP 链与峰值规则一致，残差全部来自被允许的阈值统计偏差（每窗中位数 vs 4 s 块中位数），导致约 1–3 个事件差异；事件集完全相同的 31.4% 录音上，HR 一致率 **98.6%**。估计器在小样本下脆弱：±2 bpm 一致率随标注事件数 <10 为 52%、10–19 为 64%、20–39 为 81%、≥40 为 **90%**；CirCor 只标注代表性片段 |
| 判定 | **接受"近失"**：判据 1 是"与参考实现相同"的保真代理，不是产品指标；事件级保真已独立证明，产品指标（对真值 MAE）通过且更优。不因此回退 |
| 设备真实数字 | **不得引用离线 1.19 bpm 中位数**：去掉标注掩码 + 32 事件历史（即设备实际条件）后，对参考 MAE **8.14 bpm**、±2 bpm 仅 **41.5%**。掩码的影响大于历史深度（带掩码 last-32 为 67.9%） |
| 主要风险 | 与 Python 不完全一致会让跨实现对比变难；阈值统计是唯一偏差源，未来任何阈值改动都要重跑该对照 |
| 回退 | 若要求严格一致：实现候选 D（4 s 包络中位数，可对包络子采样到 25–50 Hz，仅数百字节），代价是新增实现与一轮验证 |
| 验证 | `ctest` 4/4；`./build/test_hr_detector --fixture data/reports/hr-fixture-circor.csv` 复跑对照；上板后实测 |
| 未验证 | ESP32-S3 上的实际时延、栈占用与功耗；本轮只有 PC 数据 |
| 受影响文件 | `shared/include/hr_detector.h`、`shared/src/hr_detector.c`、`tests/test_hr_detector.c`、`tools/ai/dump_hr_fixture.py`、`CMakeLists.txt`、`firmware/**`（接入中） |

### ADR-013 三处遗留修复（2026-10-18）

| 项目 | 内容 |
| --- | --- |
| 修复 1：窗口参数未进缓存键 | 缓存只校验划分（kind/path/fold/fingerprint/seed/ratio），改 `window_sec`、`hop_sec`、`max_windows_per_record`、`window_selection` 不会失效，会静默复用旧窗口。新增 `WINDOW_CACHE_FIELDS` + `window_cache_key()` + `window_cache_matches()`，与划分键**分开校验**（两者独立，必须同时匹配）。实测：改 `--window-sec 3.0` 触发重建，再跑同参数则静默复用 |
